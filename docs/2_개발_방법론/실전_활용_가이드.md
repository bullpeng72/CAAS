### 시작 전 질문 체크리스트

프로젝트를 시작하기 전에 다음 질문에 답하세요:

```
□ 1. 이 시스템의 핵심 가치는 무엇인가요?
   예: "고객 문의 응답 시간을 10분에서 1분으로 단축"

□ 2. 주요 사용자는 누구인가요?
   예: "내부 고객 지원팀 (5명)"

□ 3. 입력은 무엇이고 출력은 무엇인가요?
   예: 입력 "고객 이메일", 출력 "분류 결과 + 추천 답변"

□ 4. 실시간인가요, 배치인가요?
   예: "실시간 (5초 이내 응답)"

□ 5. 데이터를 저장해야 하나요?
   예: "네, 처리 이력을 DB에 저장"

□ 6. 외부 API를 호출하나요?
   예: "네, Gmail API와 OpenAI API"

□ 7. 예산이 있나요?
   예: "OpenAI API 월 $50 한도"
```

## 도메인 선택 완벽 가이드

### 17개 지원 도메인 상세 설명

#### 1. TASK_MANAGEMENT (작업 관리)

**적합한 프로젝트**:
- 할일 관리 앱
- 프로젝트 추적 시스템
- 일정 관리

**전략**: CRUD_BASED (빠른 개발)

**생성 코드**:
- FastAPI CRUD API
- SQLAlchemy 모델
- Streamlit UI (선택적)

**실제 예시**:
```bash
# 대학 과제: 팀 프로젝트 관리
caas generate "팀 프로젝트 관리 시스템 - 태스크 생성, 할당, 진행 상태 추적" \
  --domain TASK_MANAGEMENT \
  --output ./team-task-manager
```

**예상 결과**:
- Agent: 최소 (1-2개)
- API 엔드포인트: 5-7개 (CRUD)
- DB 테이블: 2-3개
- 생성 시간: ~90초

---

#### 2. CONVERSATIONAL_AI (대화형 AI)

**적합한 프로젝트**:
- 챗봇
- 가상 어시스턴트
- 대화형 인터페이스

**전략**: AGENT_BASED (멀티 에이전트)

**생성 코드**:
- CrewAI Agents (3-5개)
- Chat UI
- 대화 컨텍스트 관리

**실제 예시**:
```bash
# 스타트업: 고객 지원 챗봇
caas generate "FAQ 기반 고객 지원 챗봇 - 질문 이해, FAQ 검색, 답변 생성" \
  --domain CONVERSATIONAL_AI \
  --output ./support-chatbot
```

**예상 결과**:
- Agents: 3-4개 (이해, 검색, 생성, 피드백)
- Workflow: sequential
- 생성 시간: ~120초

---

#### 3. CONTENT_CREATION (콘텐츠 생성)

**적합한 프로젝트**:
- 블로그 자동 작성
- 소셜 미디어 포스트 생성
- 마케팅 카피 작성

**전략**: AGENT_BASED

**생성 코드**:
- Content Generator Agents
- SEO Optimizer
- 다양한 포맷 지원

**실제 예시**:
```bash
# 마케팅 팀: 블로그 자동 생성
caas generate "SEO 최적화 블로그 글 생성 - 키워드 분석, 초안 작성, SEO 최적화, HTML 변환" \
  --domain CONTENT_CREATION \
  --workflow-type hierarchical \
  --output ./blog-generator
```

**예상 결과**:
- Agents: 4-5개 (연구, 작성, 최적화, 검증, 변환)
- Manager Agent: 1개 (hierarchical)
- 생성 시간: ~150초

---

#### 4. WORKFLOW_AUTOMATION (워크플로우 자동화)

**적합한 프로젝트**:
- 이메일 자동 처리
- 데이터 파이프라인
- 승인 프로세스 자동화

**전략**: HYBRID (Agent + CRUD)

**생성 코드**:
- 워크플로우 엔진
- State Machine
- DB + Agents

**실제 예시**:
```bash
# 기업: 지출 승인 자동화
caas generate "지출 승인 워크플로우 - 신청서 검증, 정책 확인, 승인자 라우팅, 알림" \
  --domain WORKFLOW_AUTOMATION \
  --deployment docker \
  --output ./expense-approval
```

**예상 결과**:
- Agents: 3-4개
- DB 테이블: 4-5개 (신청, 승인 이력, 정책)
- 생성 시간: ~180초

---

#### 5. DATA_ANALYSIS (데이터 분석)

**적합한 프로젝트**:
- 데이터 대시보드
- 리포트 자동 생성
- 통계 분석

**전략**: HYBRID

**생성 코드**:
- 데이터 처리 Agents
- 분석 도구
- 시각화 (Streamlit)

**실제 예시**:
```bash
# 분석가: 매출 리포트 자동화
caas generate "매출 데이터 분석 및 리포트 - CSV 로드, 통계 분석, 차트 생성, PDF 출력" \
  --domain DATA_ANALYSIS \
  --output ./sales-report-generator
```

**예상 결과**:
- Agents: 2-3개 (로더, 분석, 시각화)
- 생성 시간: ~120초

## 요구사항 작성 베스트 프랙티스

### ✅ 좋은 요구사항의 특징

1. **구체적인 동사 사용**
   ```
   ❌ 나쁜 예: "할일 관리 시스템"
   ✅ 좋은 예: "할일을 추가, 수정, 삭제, 완료 표시할 수 있는 시스템"
   ```

2. **입출력 명시**
   ```
   ❌ 나쁜 예: "챗봇"
   ✅ 좋은 예: "사용자 질문을 입력받아 FAQ에서 답변을 찾아 반환하는 챗봇"
   ```

3. **핵심 기능 나열**
   ```
   ❌ 나쁜 예: "전자상거래"
   ✅ 좋은 예: "상품 등록, 장바구니 추가, 결제, 주문 조회 기능이 있는 전자상거래"
   ```

4. **제약사항 포함**
   ```
   ❌ 나쁜 예: "실시간 채팅"
   ✅ 좋은 예: "5초 이내 응답하는 실시간 채팅 (동시 접속 100명 지원)"
   ```

**목적**: [시스템의 목적 1문장]

**주요 기능**:
- [기능 1]: [설명]
- [기능 2]: [설명]
- [기능 3]: [설명]

**출력**: [무엇을 출력하는지]

## 실전 케이스 스터디

### 케이스 스터디 1: 대학 팀 프로젝트 - 일정 관리 시스템

#### 📌 배경
- **팀**: 4명 (개발 2, 기획 1, 디자인 1)
- **기간**: 2주
- **목표**: 팀원들의 일정을 공유하고 회의 시간을 자동 제안
- **제약**: 무료 API만 사용, 배포 필수

#### 📝 요구사항 작성

```
"팀 일정 관리 및 회의 시간 제안 시스템

**주요 기능**:
1. 개인 일정 등록: 각 팀원이 자신의 일정 입력
2. 일정 공유: 팀원들의 일정을 캘린더 형식으로 조회
3. 회의 시간 제안: 모든 팀원이 가능한 시간대 3개 추천

from concurrent.futures import ThreadPoolExecutor

async def process_documents(documents: list):
    with ThreadPoolExecutor(max_workers=10) as executor:
        loop = asyncio.get_event_loop()
        tasks = [
            loop.run_in_executor(executor, process_doc, doc)
            for doc in documents
        ]
        results = await asyncio.gather(*tasks)
    return results

    ├── develop (개발)
    │   ├── feature/generate-code (CAAS 생성)
    │   ├── feature/implement-logic (비즈니스 로직)
    │   └── feature/add-tests (테스트)
    └── hotfix/fix-bug
```

### 코드 리뷰 체크리스트

CAAS로 생성된 코드를 리뷰할 때:

```
□ tools.py: 실제 로직 구현되었는가?
□ agents.py: 파라미터가 적절한가? (max_iter, temperature)
□ tasks.py: 의존성이 올바른가?
□ crew.py: Workflow 타입이 적절한가?
□ tests/: 테스트 커버리지 80% 이상인가?
□ .env.example: 필요한 환경 변수가 모두 나열되었는가?
□ README.md: 실행 방법이 명확한가?
□ requirements.txt: 버전이 고정되었는가?
```

## 프로덕션 체크리스트

### 배포 전 필수 체크

#### 1. 보안

```
□ API 키를 .env 파일에 저장 (코드에 하드코딩 금지)
□ .gitignore에 .env 추가
□ Secret Management 사용 (AWS Secrets Manager, Vault)
□ HTTPS 사용
□ 입력 검증 (SQL Injection, XSS 방지)
□ Rate Limiting 설정
□ 로그에 민감 정보 제외
```

#### 2. 성능

```
□ 부하 테스트 (100 동시 요청)
□ 응답 시간 < 5초 (95 percentile)
□ 메모리 사용량 < 2GB
□ 캐싱 활성화
□ DB 인덱스 설정
□ CDN 사용 (정적 파일)
```

#### 3. 모니터링

```
□ 로그 수집 (ELK, CloudWatch)
□ 메트릭 수집 (Prometheus, Grafana)
□ 알림 설정 (에러율 > 5%, 응답 시간 > 10초)
□ Health Check 엔드포인트 (/health)
□ API 비용 모니터링
□ 사용자 행동 추적 (Google Analytics)
```

#### 4. 문서화

```
□ README.md (설치, 실행, 배포 방법)
□ API 문서 (Swagger/OpenAPI)
□ 아키텍처 다이어그램
□ 트러블슈팅 가이드
□ 변경 이력 (CHANGELOG.md)
```

## 일반적인 함정과 해결책

### 함정 1: 요구사항이 너무 모호

**증상**:
```bash
caas generate "AI 시스템" --output ./output
# Agent 1개만 생성, 구현률 30%
```

**원인**: "AI 시스템"이 너무 추상적

**해결**:
```bash
# ✅ 구체적으로 작성
caas generate "고객 문의 이메일을 자동 분류하고 답변 초안을 생성하는 시스템 - 이메일 수신, 긴급도 분류, FAQ 검색, 답변 생성, 담당자 전달" \
  --output ./email-classifier
```

### 함정 2: 도메인 자동 분류가 느림

**증상**:
```
Phase 0: Concretization... (2분 소요)
```

**원인**: 도메인 자동 분류는 LLM 호출 2-3회 필요

**해결**:
```bash
# ✅ 도메인 명시
caas generate "..." --domain TASK_MANAGEMENT
# Phase 0: Concretization... (30초로 단축)
```

### 함정 3: tools.py가 stub만 생성됨

**증상**:
```python
# tools.py
class CustomTool(BaseTool):
    def _run(self, input_data: str):
        # TODO: Implement
        return {"status": "stub"}
```

**원인**: 요구사항에 도구 세부사항 부족

**해결**:
```bash
# ✅ 도구 기능을 명시
caas generate "블로그 생성 - SEO 분석 도구(키워드 검색량, 경쟁도 분석), 콘텐츠 생성 도구(GPT-4로 3000자 작성), HTML 변환 도구(Markdown → HTML)" \
  --output ./blog-gen
```

### 함정 4: API 비용 폭탄

**증상**:
```
월 예상 비용: $50
실제 비용: $350 (7배!)
```

**원인**:
- GPT-4 과다 사용
- 캐싱 없음
- 긴 프롬프트

**해결**:
```bash
# ✅ 비용 제한 설정
cat > config.yaml << EOF
llm:
  daily_budget: 10          # $10/일
  model: gpt-3.5-turbo      # 저렴한 모델
  max_tokens: 500           # 토큰 제한
  cache_enabled: true       # 캐싱 활성화
EOF

# ✅ 모니터링
python scripts/monitor_cost.py
```

### 함정 5: 생성 코드를 그대로 프로덕션에 배포

**증상**:
```
tools.py에 실제 로직 없음
에러 핸들링 부족
테스트 커버리지 40%
```

**원인**: CAAS는 시작점만 제공, 100% 완성 아님

**해결**:
```bash
# ✅ 생성 후 필수 작업
# 1. tools.py 실제 로직 구현
vim src/tools.py

# 2. 에러 핸들링 추가
vim src/agents.py

# 3. 테스트 추가
vim tests/test_integration.py

# 4. 검증
caas test --coverage
# 목표: 80% 이상
```

### ⚠️ 초보자가 자주 하는 실수

1. **API 키를 .env 파일에 설정하지 않음**
   ```
   증상: OPENAI_API_KEY not found 에러
   해결: .env 파일 생성 및 키 입력
   ```

2. **가상 환경을 활성화하지 않음**
   ```
   증상: caas: command not found 에러
   해결: source venv/bin/activate 실행
   ```

3. **Python 버전이 3.11 미만**
   ```
   증상: 설치 중 에러 발생
   해결: Python 3.11 이상 설치
   ```

4. **요구사항이 너무 모호함**
   ```
   증상: 생성된 에이전트가 부족하거나 불명확
   해결: 구체적인 기능 명시 ("할일 추가, 완료 표시, 목록 보기")

## BMAD 6-Phase 프로세스

CAAS는 **BMAD (Breakthrough Method for Agile AI-driven Development)** 6-Phase 방법론을 사용합니다 (Phase 0-5).

### 전체 프로세스 다이어그램

```
┌────────────────────────────────────────────────────────────┐
│ Phase 0: Concretization (요구사항 구체화)                  │

│  역할: Golden Data Pipeline                                │

### Expert Agent Collaboration ✨

CAAS는 5명의 전문가 에이전트가 협업하여 코드를 생성합니다:

```
Requirements Analyst → System Architect → Design Specialist → Development Engineer → QA Expert
       ↓                    ↓                   ↓                      ↓                    ↓
   Golden Data         Traceability        Completeness           Generated Code      Validation
                        Matrix              Report                + Gap Filling        Report
```

**협업 모드**:
- **Sequential Mode**: 순차적 실행 (Phase 0 → 1 → 2 → 3 → 4 → 5)
- **Parallel Mode**: 병렬 실행 (일부 Phase 동시 실행, 향후 지원)

### Phase별 상세 설명

#### Phase 0: Concretization (요구사항 구체화)

**목적**: 자연어 요구사항을 구조화된 데이터로 변환

**입력**:
```
"간단한 할일 관리 시스템 - 사용자가 할일을 추가하고 완료 표시할 수 있음"
```

**처리**:
1. LLM을 사용하여 요구사항 분석
2. 도메인 자동 분류 (17개 도메인 중)
3. 기능 추출
4. 데이터 모델 추론

**출력** (`golden_data.json`):
```json
{
  "project_name": "todo_management",
  "domain": "TASK_MANAGEMENT",
  "features": [
    {
      "id": "F1",
      "name": "Add Todo",
      "description": "Allow users to add new todo items",
      "priority": "high"
    },
    {
      "id": "F2",
      "name": "Mark Complete",
      "description": "Allow users to mark todos as complete",
      "priority": "high"
    }
  ],
  "data_models": [
    {
      "entity_name": "Todo",
      "attributes": [
        {"name": "id", "type": "int", "required": true},
        {"name": "title", "type": "string", "required": true},
        {"name": "completed", "type": "boolean", "required": true}
      ]
    }
  ]
}
```

#### Phase 1: Discovery (요구사항 분석)

**목적**: 요구사항의 완전성 검증 및 Gap 분석

**처리**:
1. 기능 완전성 확인
2. 누락된 요구사항 발견
3. 모호한 부분 명확화
4. 우선순위 조정

**출력** (`requirement_analysis.json`):
```json
{
  "analysis_result": "COMPLETE",
  "identified_gaps": [
    "Missing: Todo deletion functionality",
    "Missing: Todo editing functionality",
    "Missing: Error handling specification"
  ],
  "recommendations": [
    "Add delete todo feature",
    "Add edit todo feature",
    "Specify error handling strategy"
  ]
}
```

#### Phase 2: Architecture (시스템 설계) ✨

**🆕 신기능 (2026-01-31)**: Traceability Matrix 구축

**목적**: 시스템 아키텍처 설계 및 코드 생성 전략 결정

**처리**:
1. 도메인 기반 전략 선택 (AGENT_BASED / CRUD_BASED / HYBRID)
2. 트레이서빌리티 매트릭스 생성
3. 시스템 구조 설계

**출력** (`architecture.json`):
```json
{
  "strategy": "AGENT_BASED",
  "workflow_type": "sequential",
  "agent_count_estimate": 2,
  "task_count_estimate": 3,
  "requires_database": false,
  "requires_api": false,
  "requires_frontend": false
}
```

#### Phase 3: Design (에이전트/태스크 설계) ✨

**🆕 신기능 (2026-01-31)**: Completeness Validation (완전성 검증)

**목적**: 구체적인 에이전트와 태스크 설계

**처리**:
1. 기능별 에이전트 생성
2. 에이전트별 도구 할당
3. 태스크 생성 및 의존성 설정
4. **한국어 도구명 자동 처리**

**출력** (`agents.json`, `tasks.json`):
```json
// agents.json
[
  {
    "id": "todo_manager",
    "role": "할일 관리자",
    "goal": "할일 추가 및 완료 표시",
    "backstory": "할일 관리 전문가",
    "tools": ["데이터베이스", "입력 검증 도구"],
    "verbose": true,
    "allow_delegation": false,
    "max_iter": 15
  }
]

// tasks.json
[
  {
    "id": "add_todo_task",
    "description": "새로운 할일을 추가합니다",
    "expected_output": "추가된 할일 정보",
    "agent": "todo_manager",
    "context": [],
    "async_execution": false
  }
]
```

#### Phase 4: Development (코드 생성) ✨

**🆕 신기능 (2026-01-31)**: Gap Filling (자동 코드 생성) + 3-Layer Defense

**목적**: 프로덕션 레디 Python 코드 생성

**처리**:
1. **tools.py 생성** (3단계 방어 메커니즘)
   - Sanitization: "데이터베이스" → "DatabaseTool"
   - LLM 생성: BaseTool 상속, 에러 핸들링 포함
   - Fallback: LLM 실패 시 stub 생성
2. agents.py 생성
3. tasks.py 생성
4. crew.py 생성 (Crew 구성)
5. main.py 생성 (진입점)
6. 테스트 파일 생성
7. Docker 파일 생성
8. requirements.txt 생성

**출력** (22개 파일):
```
generated/
├── main.py
├── requirements.txt
├── README.md
├── .env.example
├── src/
│   ├── agents.py      ✅ 에이전트 정의
│   ├── tasks.py       ✅ 태스크 정의
│   ├── tools.py       ✨ LLM 생성 (항상 생성 보장!)
│   └── crew.py        ✅ Crew 구성
├── tests/
│   ├── test_agents.py
│   ├── test_tasks.py
│   └── test_integration.py
├── Dockerfile
└── docker-compose.yml
```

**tools.py 예시** (LLM 생성):
```python
from crewai.tools import BaseTool
from typing import Any
import logging

logger = logging.getLogger(__name__)

class DatabaseTool(BaseTool):
    name: str = "database_tool"
    description: str = "Tool for database operations"

    def _run(self, query: str) -> Any:
        """Execute database query"""
        logger.info(f"Executing query: {query}")
        try:
            # 실제 로직
            result = execute_db_query(query)
            return result
        except Exception as e:
            logger.error(f"Database error: {e}")
            raise
```

4. 트레이서빌리티 업데이트

## FAQ

### Q1: BMAD 6단계를 건너뛸 수 있나요?

**A**: 아니오. 모든 단계가 순차적으로 필요합니다. 각 단계의 출력이 다음 단계의 입력이 됩니다.

### Q2: tools.py가 항상 생성되나요?

**A**: 네! (2026-01-31 업데이트 이후) 3단계 방어 메커니즘으로 항상 생성됩니다:
1. LLM 생성 시도
2. 실패 시 Fallback stub 생성
3. 도구가 없어도 빈 템플릿 생성

### Q3: 한국어 요구사항도 지원하나요?

**A**: 네! 한국어 요구사항을 입력해도 정상 작동합니다. LLM이 자동으로 이해하고 처리합니다.

```bash
caas generate "간단한 할일 관리 시스템" --output ./output
# ✅ 정상 작동
```

### Q4: 완전성 검증 점수가 낮으면?

**A**: 60% 이상이면 정상입니다. 100%는 달성하기 어렵습니다:
- 70%+: 우수
- 60-70%: 양호
- 50-60%: 보통 (추가 구현 필요)
- 50% 미만: 재생성 권장

### Q5: 생성 시간을 줄일 수 있나요?

**A**: 네, 몇 가지 방법이 있습니다:
```bash
# 1. 간단한 요구사항 작성
caas generate "할일 추가 기능만" --output ./simple

# 2. 도메인 명시 (자동 분류 건너뛰기)
caas generate "..." --domain TASK_MANAGEMENT

# 3. 검증 건너뛰기 (권장하지 않음)
caas generate "..." --no-completeness
```

### Q6: 생성된 코드를 수정해도 되나요?

**A**: 네! 생성된 코드는 시작점입니다. 자유롭게 수정하세요:
- tools.py: 실제 비즈니스 로직 구현
- agents.py: 에이전트 파라미터 조정
- tasks.py: 태스크 로직 개선
- crew.py: Crew 구성 변경

### Q7: 프로덕션에서 사용해도 되나요?

**A**: 네, 하지만 다음을 확인하세요:
- ✅ 보안 감사 (API 키, 민감 정보)
- ✅ 에러 핸들링 강화
- ✅ 로깅 및 모니터링 설정
- ✅ 테스트 커버리지 80% 이상
- ✅ 성능 테스트

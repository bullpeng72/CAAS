## 🎯 방법론 이론

### CAAS의 핵심 방법론 체계

CAAS는 세 가지 핵심 방법론을 통합하여 프로덕션 레디 코드를 생성합니다:

```
┌─────────────────────────────────────────────────┐
│         BMAD 6-Phase Methodology                │
│  (Build-Measure-Analyze-Deploy-Assure-Deliver) │
└─────────────────┬───────────────────────────────┘
                  │
         ┌────────┴────────┐
         │                 │
┌────────▼────────┐ ┌─────▼──────────┐
│   Spec-Driven   │ │      TDD       │
│   Development   │ │  Integration   │
└─────────────────┘ └────────────────┘
```

### 1.1 BMAD 방법론 (Build-Measure-Analyze-Deploy)

BMAD는 CAAS의 핵심 워크플로우로, 6개 Phase로 구성됩니다:

#### 이론적 배경

**BMAD**는 전통적인 소프트웨어 개발 생명주기(SDLC)를 AI 기반 코드 생성에 최적화한 방법론입니다:

1. **Build** (Phase 0-1): 요구사항 구체화 및 분석
2. **Measure** (Phase 2): 추적성 측정 및 검증
3. **Analyze** (Phase 3): 완전성 분석 및 설계
4. **Deploy** (Phase 4-5): 코드 생성 및 배포 준비

#### Phase별 품질 게이트

각 Phase 사이에는 **Quality Gate**가 존재하여 다음 Phase로의 진행 여부를 결정합니다:

```python
# caas_framework/agents/collaboration.py (v1.0.0 - 임시 우회)

async def _evaluate_quality_gate(
    phase: AgentPhase,
    output: Dict[str, Any]
) -> Optional[GateEvaluation]:
    """
    Quality Gate 평가 (v1.0.0: 임시 우회)

    v1.1.0에서 재활성화 예정:
    - Coverage 검증 (80% 이상)
    - Consistency 검증 (90% 이상)
    - Completeness 검증 (85% 이상)
    """
    # 현재는 우회되어 있으나, 향후 다음 기준 적용:
    # 1. Traceability Score >= 0.8
    # 2. Completeness Rate >= 0.85
    # 3. No Critical Errors
    pass
```

### 1.2 Spec-Driven Development (SDD)

#### 정의

**Spec-Driven Development**는 상세한 스펙(Specification)을 먼저 작성하고, 이를 기반으로 코드를 생성하는 개발 방법론입니다.

#### CAAS에서의 적용

```
요구사항 (Natural Language)
    ↓
Golden Data (구조화된 스펙)
    ↓
Agent/Task Spec (JSON)
    ↓
Architecture Spec (JSON)
    ↓
Production Code (Python)
```

**핵심 원칙**:
1. **스펙 우선**: 코드 전에 스펙을 완성
2. **추적성 보장**: 모든 코드는 스펙으로 추적 가능
3. **검증 가능성**: 스펙 기반 자동 검증

#### 실제 예시: Golden Data

```json
{
  "project_name": "E-Commerce Platform",
  "domain": "E_COMMERCE",
  "features": [
    {
      "id": "F001",
      "name": "사용자 인증",
      "description": "JWT 기반 로그인/로그아웃",
      "priority": "HIGH",
      "dependencies": []
    },
    {
      "id": "F002",
      "name": "상품 카탈로그",
      "description": "상품 검색, 필터링, 정렬",
      "priority": "HIGH",
      "dependencies": ["F001"]
    },
    {
      "id": "F003",
      "name": "장바구니",
      "description": "장바구니 추가/삭제/수량 변경",
      "priority": "MEDIUM",
      "dependencies": ["F001", "F002"]
    }
  ],
  "non_functional_requirements": {
    "scalability": "10,000 concurrent users",
    "availability": "99.9%",
    "performance": "Response time < 200ms"
  }
}
```

### 1.3 Test-Driven Development (TDD) 통합

#### CAAS의 TDD 지원

CAAS는 코드 생성 시 자동으로 테스트 코드를 생성합니다:

```python
# 생성된 tests/test_agents.py 예시

import pytest
from src.agents import create_agents

class TestAgents:
    """에이전트 기능 테스트"""

    def setup_method(self):
        """각 테스트 전 실행"""
        self.agents = create_agents()

    def test_agent_creation(self):
        """에이전트 생성 테스트"""
        assert len(self.agents) > 0
        assert "user_auth_agent" in self.agents

    def test_agent_tools(self):
        """에이전트 도구 할당 테스트"""
        agent = self.agents["user_auth_agent"]
        assert agent.tools is not None
        assert len(agent.tools) > 0

    def test_agent_delegation(self):
        """에이전트 위임 설정 테스트"""
        for agent in self.agents.values():
            assert agent.allow_delegation is not None
```

#### TDD 사이클

```
1. 요구사항 분석 → 테스트 케이스 정의 (Phase 3)
2. 코드 생성 (Phase 5)
3. 테스트 실행 (Phase 5)
4. 실패한 테스트 → 코드 수정 (Gap Filling)
5. 모든 테스트 통과 → 배포 준비
```

## 🏗️ 대규모 프로젝트 생성 전략

### 전략 1: 단계적 접근 (Incremental Approach)

대규모 프로젝트는 한 번에 생성하지 않고 단계적으로 구축합니다.

#### Step 1: 핵심 기능 우선 생성

```bash
# Phase 1: 인증 시스템만 먼저 생성
caas generate "사용자 인증 시스템: 회원가입, 로그인, JWT 토큰 관리" \
  --domain CONVERSATIONAL_AI \
  --output ./ecommerce-auth \
  --verbosity verbose

# 검증
cd ecommerce-auth
pytest tests/
```

#### Step 2: 기능 확장

```bash
# Phase 2: 상품 카탈로그 추가
caas expand "E-Commerce 플랫폼에 상품 카탈로그 기능 추가: 검색, 필터링, 정렬" \
  --golden-data ./ecommerce-auth/golden_data.json \
  --output expanded_golden.json

# 재생성
caas generate "E-Commerce 플랫폼" \
  --golden-data expanded_golden.json \
  --output ./ecommerce-v2
```

#### Step 3: 통합 및 최적화

```bash
# 검증
caas validate --validator all \
  --agents ./ecommerce-v2/agents.json \
  --tasks ./ecommerce-v2/tasks.json \
  --golden-data ./ecommerce-v2/golden_data.json

# 자동 수정
caas fix \
  --agents ./ecommerce-v2/agents.json \
  --tasks ./ecommerce-v2/tasks.json \
  --golden-data ./ecommerce-v2/golden_data.json \
  --level 3 \
  --output ./ecommerce-fixed
```

### 4. 코드 품질 향상

#### tools.py 3-Layer Defense (v1.1.0 예정)

**⚠️ v1.0.0 중요 제약사항**: 현재 버전에서는 `tools.py` 생성 기능이 비활성화되어 있습니다.

**v1.1.0 예정 기능** - CAAS는 항상 실행 가능한 `tools.py`를 생성하기 위해 3단계 방어 메커니즘을 사용할 예정입니다:

```python
# Layer 1: Validation (한국어 → 영어 변환)
tool_name_kr = "파일_읽기_도구"
tool_name_en = semantic_mapper.translate(tool_name_kr)
# 결과: "FileReadTool"

# Layer 2: LLM Generation (BaseTool 상속)
tool_code = llm.generate_tool_code(
    tool_name=tool_name_en,
    description="파일을 읽어서 내용을 반환하는 도구",
    base_class="BaseTool"
)

# Layer 3: Fallback (LLM 실패 시 stub 생성)
if not tool_code or has_errors(tool_code):
    tool_code = generate_stub_tool(tool_name_en)
```

**v1.1.0 목표**: 100% 실행 가능한 tools.py 생성 보장

```python
)

# ✅ 수정 후 (옵션 2: 직접 tools.py 작성)
# tools.py 파일을 수동 작성한 후:
from tools import FileReadTool, FileWriteTool

agents["auth_agent"] = Agent(
    role="인증 에이전트",
    goal="...",
    backstory="...",
    tools=[FileReadTool(), FileWriteTool()],
)
```

**자동 수정 스크립트**:
```bash
# agents.py의 모든 tools 할당을 빈 리스트로 변경
sed -i 's/tools=\[.*\]/tools=[]/' agents.py
```

## ⚠️ 알려진 문제 및 해결방법 (v1.0.0)

### 문제 1: NameError - 도구 미정의 ⭐ 가장 흔한 문제

**증상**:
```python
NameError: name 'file_read' is not defined
NameError: name 'file_write' is not defined
```

**원인**:
- `tools.py` 파일이 생성되지 않음 (v1.0.0 제약사항)
- `agents.py`에서 정의되지 않은 도구를 참조

**해결방법 1** - 도구 제거 (권장):
```bash
# 자동 수정
cd <프로젝트_디렉토리>
sed -i 's/tools=\[.*\]/tools=[]/' agents.py

# 또는 수동 수정
vi agents.py
# tools=[file_read, file_write] → tools=[]로 변경
```

**해결방법 2** - tools.py 직접 작성:
```python
# tools.py (수동 작성)
from crewai.tools import BaseTool
from typing import Type
from pydantic import BaseModel, Field

class FileReadTool(BaseTool):
    name: str = "file_read"
    description: str = "Read contents from a file"

    def _run(self, file_path: str) -> str:
        with open(file_path, 'r') as f:
            return f.read()

class FileWriteTool(BaseTool):
    name: str = "file_write"
    description: str = "Write contents to a file"

    def _run(self, file_path: str, content: str) -> str:
        with open(file_path, 'w') as f:
            f.write(content)
        return f"Written to {file_path}"
```

그 후 `agents.py` 수정:
```python
from tools import FileReadTool, FileWriteTool

agents["auth_agent"] = Agent(
    ...
    tools=[FileReadTool(), FileWriteTool()],
)
```

### 문제 2: 완전성 검증 불일치

**증상**:
- 같은 코드에서 완전성 점수가 100%와 0%로 번갈아 나타남
- 검증 시스템이 "통과"하지만 실제 코드 실행 실패

**원인**:

- AST 파싱만 수행하고 실제 import/실행 테스트 안 함

**해결방법**:
```bash
# 검증 결과를 맹신하지 말고 반드시 수동 테스트
python -c "from agents import create_agents; agents = create_agents()"

# 오류 발생 시 위의 "문제 1" 해결방법 적용
```

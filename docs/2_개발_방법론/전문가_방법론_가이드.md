## 🎯 방법론 이론

CAAS는 세 가지 핵심 방법론을 통합하여 프로덕션 레디 코드를 생성합니다:

1.  **BMAD 6-Phase 방법론**: 요구사항 분석부터 코드 생성, 품질 보증까지 이어지는 핵심 워크플로우입니다.
2.  **Spec-Driven Development (SDD)**: 상세한 스펙(Golden Data, Agent/Task Spec 등)을 먼저 정의하고 이를 기반으로 코드를 생성하여 예측 가능성과 검증 가능성을 높입니다.
3.  **Test-Driven Development (TDD) 통합**: 코드 생성 시 테스트 코드를 함께 생성하여 코드의 안정성을 보장합니다.

### 1.1 Expert Agent Collaboration
5개의 전문가 에이전트(요구사항 분석가, 시스템 아키텍트, 에이전트 설계자, QA 엔지니어, 코드 생성기)가 각자의 전문 분야를 맡아 협업하며, 사람의 개발 프로세스를 모방하여 고품질의 산출물을 생성합니다.

## 🔄 BMAD 6-Phase 심화

각 Phase는 독립적으로 실행될 수 있으며, 특정 Phase의 결과물을 입력으로 다음 Phase를 진행할 수 있습니다. 이는 대규모 프로젝트를 단계적으로 구축하는 데 핵심적인 역할을 합니다.

- **Phase 0: Concretization (요구사항 구체화)**: 자연어 요구사항을 구조화된 `Golden Data`로 변환합니다.
- **Phase 1: Discovery (요구사항 분석)**: `Golden Data`를 분석하여 도메인을 특정하고 요구사항 명세를 생성합니다.
- **Phase 2: Architecture (시스템 설계)**: 시스템 아키텍처를 설계하고 `Traceability Matrix`를 생성합니다.
- **Phase 3: Design (에이전트/태스크 설계)**: CrewAI 에이전트 및 태스크를 상세히 설계하고 `Completeness Validation`을 수행합니다.
- **Phase 4: Development (코드 스펙 생성)**: 코드 생성을 위한 상세 스펙을 작성합니다.
- **Phase 5: Delivery (코드 생성 및 배포)**: 프로덕션 레디 코드를 생성하고, 필요시 `Gap Filling`을 통해 누락된 부분을 보완합니다.

## 🏗️ 대규모 프로젝트를 위한 CLI 워크플로우 전략

대규모 프로젝트를 한 번에 완벽하게 생성하는 것은 비현실적입니다. 대신, CAAS의 다양한 CLI 명령어들을 조합하여 **점진적이고 반복적으로 시스템을 구체화하고 완성**하는 것이 전문가적인 접근 방식입니다.

### 핵심 전략: 반복적 정제 (Iterative Refinement)

이 전략은 초기 아이디어를 빠르게 프로토타이핑하고, 시스템의 분석 기능을 통해 부족한 부분을 찾아낸 뒤, 사용자와 상호작용하며 요구사항을 구체화하고, 이를 바탕으로 시스템을 점차 완성해나가는 과정입니다.

**워크플로우 순서:**

1.  **초기 생성 (`generate`)**: 모호한 초기 요구사항으로 빠르게 첫 버전을 생성하여 `Golden Data`와 기본 구조를 확보합니다.
2.  **갭 분석 (`analyze-gaps`)**: 생성된 `Golden Data`를 기반으로 시스템이 자동으로 부족하거나 누락된 요구사항(Gaps)을 분석합니다.
3.  **대화형 명확화 (`questions`)**: 분석된 갭에 대해 사용자에게 구체적인 질문을 던져 요구사항을 명확히 합니다.
4.  **자동 확장 (`expand`)**: 명확해진 요구사항을 바탕으로 기존 `Golden Data`를 자동으로 확장하고 구체화합니다.
5.  **재생성 (`generate` with Golden Data)**: 확장된 `Golden Data`를 입력으로 사용하여 훨씬 더 완성도 높은 버전의 시스템을 생성합니다.
6.  **검증 및 수정 (`validate`, `fix`)**: 생성된 설계의 논리적 오류나 비일관성을 검증하고 자동으로 수정합니다.
7.  **컴포넌트 단위 재생성 (`codegen`)**: 전체를 재생성할 필요 없이, 특정 부분(e.g., `tools.py`)만 다시 생성하여 미세 조정합니다.
8.  **세션 관리 (`session`)**: 복잡한 프로젝트 작업을 세션으로 저장하고, 여러 프로젝트를 동시에 관리합니다.

## 💼 실전: E-Commerce 플랫폼 구축 (CLI 워크플로우)

**목표**: 완전한 기능을 갖춘 E-Commerce 플랫폼을 "반복적 정제" 전략을 통해 구축

### Step 1: 프로젝트 세션 시작 및 초기 프로토타입 생성

먼저, `session` 명령어로 이커머스 프로젝트를 위한 작업 공간을 만듭니다. 그리고 매우 간단한 초기 요구사항으로 첫 버전을 생성하여 전체적인 뼈대를 잡습니다.

```bash
# 1. 새 프로젝트를 위한 세션 생성
caas session create ecommerce-project

# 2. 간단한 요구사항으로 초기 버전 생성
caas generate "E-Commerce platform" \
  --domain E_COMMERCE \
  --output ./ecommerce-v1
```
- **결과**: `./ecommerce-v1` 디렉토리에 기본 구조와 `artifacts/golden_data.json`이 생성됩니다. 이 `golden_data.json`은 아직 기능이 부족한 상태입니다.

### Step 2: 갭 분석 및 대화형 요구사항 정제

이제 CAAS의 분석 기능을 사용하여 초기 결과물의 부족한 부분을 찾아내고, `questions` 명령어로 시스템과 대화하며 요구사항을 구체화합니다.

```bash
# 3. 생성된 Golden Data를 기반으로 갭 분석 수행
caas analyze-gaps "E-Commerce platform" \
  --golden-data ./ecommerce-v1/artifacts/golden_data.json \
  --output ./ecommerce-v1/artifacts/gaps.json

# 4. 분석된 갭에 대해 시스템과 대화하며 요구사항 구체화
caas questions --gaps ./ecommerce-v1/artifacts/gaps.json --domain E_COMMERCE
```
- **실행 화면 예시**:
  ```
  Q1: 결제 게이트웨이는 어떤 것을 사용하시나요?
      a) Stripe b) PayPal c) 직접 구현
  입력: a

  Q2: 상품 추천 알고리즘은 어떤 방식이 필요한가요?
      a) 협업 필터링 b) 콘텐츠 기반 c) AI 기반
  입력: c
  ... (중략)
  ✅ 응답이 세션에 저장되었습니다.
  ```
- **결과**: 사용자의 답변이 현재 세션에 저장되어 다음 `expand` 단계에서 활용됩니다.

### Step 3: 요구사항 자동 확장 및 v2 생성

수집된 답변을 바탕으로 초기 `Golden Data`를 자동으로 확장하고, 이 확장된 명세를 이용해 훨씬 정교한 두 번째 버전을 생성합니다.

```bash
# 5. 수집된 답변으로 Golden Data 자동 확장
caas expand "E-Commerce platform" \
  --gaps ./ecommerce-v1/artifacts/gaps.json \
  --golden-data ./ecommerce-v1/artifacts/golden_data.json \
  --output ./ecommerce-v2/artifacts/expanded_golden.json

# 6. 확장된 Golden Data로 v2 프로젝트 생성
caas generate "Fully-featured E-Commerce platform" \
  --golden-data ./ecommerce-v2/artifacts/expanded_golden.json \
  --output ./ecommerce-v2
```
- **결과**: v1에 비해 기능, 에이전트, 태스크가 훨씬 풍부하고 구체적인 `./ecommerce-v2`가 생성됩니다.

### Step 4: 검증, 자동 수정 및 추적성 확인

v2 결과물에 대해 논리적 오류나 불일치가 없는지 검증하고, 발견된 문제를 자동으로 수정합니다. 마지막으로 모든 요구사항이 코드에 잘 반영되었는지 추적성 매트릭스를 생성하여 확인합니다.

```bash
# 7. 생성된 설계의 모든 측면 검증
caas validate --validator all \
  --agents ./ecommerce-v2/artifacts/agents.json \
  --tasks ./ecommerce-v2/artifacts/tasks.json \
  --golden-data ./ecommerce-v2/artifacts/expanded_golden.json

# 8. (필요시) 검증에서 발견된 이슈 자동 수정 (LLM 기반)
caas fix --level 3 \
  --agents ./ecommerce-v2/artifacts/agents.json \
  --tasks ./ecommerce-v2/artifacts/tasks.json \
  --output ./ecommerce-v2/fixed

# 9. 요구사항부터 코드까지의 추적성 리포트 생성
caas traceability \
  --golden-data ./ecommerce-v2/artifacts/expanded_golden.json \
  --agents ./ecommerce-v2/fixed/agents.json \
  --tasks ./ecommerce-v2/fixed/tasks.json \
  --code ./ecommerce-v2/src \
  --output ./ecommerce-v2/traceability_report.md
```
- **결과**: 논리적으로 검증되고, 요구사항 추적이 가능한 안정적인 코드베이스가 완성됩니다.

### Step 5: 최종 코드 실행 및 테스트

이제 생성된 코드를 실행하고, 자동 생성된 테스트를 수행하여 최종 검증을 마칩니다.

```bash
cd ./ecommerce-v2

# 1. 의존성 설치
pip install -r requirements.txt

# 2. 환경 변수 설정
cp .env.example .env
nano .env  # API 키 입력

# 3. 메인 애플리케이션 실행
python main.py

# 4. (생성된 경우) 자동 생성된 테스트 실행
pytest tests/
```
- **결과**: 완전한 기능을 갖춘 E-Commerce 플랫폼의 초기 버전이 실행됩니다. 이제부터 개발자는 이 코드베이스를 기반으로 비즈니스 로직을 추가하고 발전시킬 수 있습니다.

## 🚀 고급 기능 활용

### 1. 컴포넌트 단위 코드 생성 (`codegen`)
전체 프로젝트를 다시 생성하지 않고 특정 부분만 미세 조정하고 싶을 때 사용합니다.
```bash
# tools.py만 최신 설계에 맞춰 다시 생성
caas codegen --component tools \
  --agents ./ecommerce-v2/fixed/agents.json \
  --output ./ecommerce-v2/src
```

### 2. Phase별 실행 (`generate-phase`)
BMAD 워크플로우를 단계별로 실행하며 각 결과물을 수동으로 검토하고 싶을 때 유용합니다.
```bash
# Phase 0, 1만 실행하여 Golden Data와 요구사항 분석 결과만 확인
caas generate-phase --phase 1 "E-commerce platform" --output ./ecommerce-phase1-output
```

### 3. Auto-Fix 아키텍처 (v0.2.0+)
`caas generate` 또는 `caas fix` 실행 시, LLM이 생성한 코드의 일반적인 버그(e.g., 잘못된 파라미터, `tools` 리스트 형식 오류, `tools.py` 누락)를 자동으로 수정하는 기능이 내장되어 있습니다. 이 덕분에 최신 버전에서는 코드 생성 성공률이 100%에 가깝습니다.

## 🎯 최적화 및 문제 해결

### `tools.py` 3-Layer Defense
CAAS는 `tools.py` 생성 실패를 방지하기 위해 3단계 방어 메커니즘을 사용합니다.
1.  **Validation**: 도구 이름 등을 검증.
2.  **LLM Generation**: LLM을 통해 코드 생성을 시도.
3.  **Fallback Generation**: LLM 생성 실패 시, 100% 실행 가능한 stub 코드를 포함한 `tools.py`를 생성.

이 메커니즘 덕분에 `tools.py` 누락으로 인한 `NameError` 문제는 대부분 해결되었습니다. 만약 오래된 버전에서 문제가 발생한다면, `from tools import ...`를 `from src.tools import ...`로 수정해야 할 수 있습니다. 최신 버전에서는 이 또한 자동으로 처리됩니다.

### 성능 및 품질 최적화
- **LLM 모델 선택**: 속도가 중요하다면 `gpt-4o-mini`, 품질이 중요하다면 `gpt-4-turbo`를 `caas config set llm_model <model_name>` 명령어로 설정할 수 있습니다.
- **상세한 요구사항**: 초기 요구사항이 상세할수록 더 적은 반복으로 고품질의 결과를 얻을 수 있습니다.
- **자동 수정 레벨**: `caas fix --level 3`는 가장 강력한 LLM 기반 수정 기능이지만, 비용과 시간이 더 소요될 수 있습니다.

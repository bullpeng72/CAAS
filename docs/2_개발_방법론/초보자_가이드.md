## 📖 이 가이드에 대하여

CAAS로 프로덕션 레디 멀티 에이전트 시스템을 만드는 **2가지 방법**을 배웁니다.

### 🎯 학습 목표

- ✅ **방법 1**: 자동화 방식 (generate 명령어 한 번으로 완성)
- ✅ **방법 2**: 단계별 방식 (BMAD 6-Phase 순차 실행)
- ✅ 각 방법에서 **고품질 결과물**을 만드는 실전 가이드
- ✅ 문제 진단 및 품질 개선 기법

### 💡 어떤 방법을 선택해야 하나요?

| 상황 | 추천 방법 | 이유 |
|------|----------|------|
| **처음 사용** | 방법 1 (자동화) | 빠르게 전체 프로세스 경험 |
| **프로토타입** | 방법 1 (자동화) | 빠른 반복 개발 |
| **프로덕션** | 방법 2 (단계별) | 각 단계 검증 및 제어 |
| **학습 목적** | 방법 2 (단계별) | BMAD 프로세스 이해 |
| **복잡한 요구사항** | 방법 2 (단계별) | 단계별 정제 및 수정 |

#### 4-2. 구현률이 낮을 때 (60% 미만)

**원인**:
- 요구사항이 너무 모호함
- 도메인이 적합하지 않음
- 웹 UI 직접 생성 요청 (미지원)

**해결책**:

**방법 A: 요구사항 정제**
```bash
# 요구사항 갭 분석
caas analyze-gaps "모호한 요구사항"

# 자동 확장
caas expand "짧은 요구사항"

# 결과를 바탕으로 다시 생성
caas generate "확장된 상세 요구사항"
```

**방법 B: 도메인 명시**
```bash
# 도메인을 명시하면 해당 도메인 최적화 적용
caas generate "금융 분석" --domain DATA_ANALYSIS
```

**방법 C: 분할 정복**
```bash
# 복잡한 시스템을 여러 에이전트로 분할
caas generate "데이터 수집 에이전트" --output ./collector
caas generate "데이터 분석 에이전트" --output ./analyzer
caas generate "리포트 생성 에이전트" --output ./reporter
```

#### 4-3. 코드 오류가 있을 때

**v0.2.0+는 자동 수정됨**:
- ✅ `id='...'` 파라미터 자동 제거
- ✅ `tools=['str']` 자동 변환
- ✅ 미지원 파라미터 자동 제거
- ✅ `tools.py` 누락 시 자동 생성

**수동 수정이 필요한 경우**:
```bash
# 검증 실행
caas validate --validator all \
  --agents ./generated/design/agents.json \
  --tasks ./generated/design/tasks.json

# 자동 수정 (Level 3: LLM 기반)
caas fix --level 3 \
  --agents ./generated/design/agents.json \
  --tasks ./generated/design/tasks.json \
  --output ./generated/design_fixed/

# 수정된 설계로 재생성
caas generate-code \
  --agents ./generated/design_fixed/agents.json \
  --tasks ./generated/design_fixed/tasks.json \
  --output ./generated_v2
```

## 🔧 방법 2: 단계별 방식 (추천: 프로덕션)

**BMAD 6-Phase를 순차적으로 실행하여 각 단계를 제어 및 검증**

### ✨ 특징

- 🎯 **세밀한 제어**: 각 단계마다 결과 확인 및 수정 가능
- ✅ **높은 품질**: 단계별 검증으로 최종 품질 향상
- 📊 **학습 효과**: BMAD 프로세스 이해
- 🔄 **반복 개선**: 원하는 단계만 재실행 가능

### 📋 BMAD 6-Phase 개요

```
Phase 0: Concretization  (요구사항 구조화)
   ↓
Phase 1: Discovery       (도메인 분석)
   ↓
Phase 2: Architecture    (시스템 설계 + Traceability)
   ↓
Phase 3: Design          (Agent/Task 설계 + Completeness)
   ↓
Phase 4: Development     (명세 생성)
   ↓
Phase 5: Delivery        (코드 생성)
```

### 📝 Step 1: Phase 0 - Concretization (Golden Data 생성)

**목적**: 자연어 요구사항을 구조화된 Golden Data로 변환

#### 1-1. Phase 0 실행

```bash
caas generate-phase --phase 0 \
  "할일 관리 시스템:
  - 할일 CRUD 기능
  - 우선순위 및 마감일 설정
  - 카테고리 분류
  - 완료 통계" \
  --output ./todo-system
```

**생성 결과**:
```

└── artifacts/
    └── golden_data.json
```

### 방법 1 vs 방법 2 상세 비교

| 항목 | 방법 1 (자동화) | 방법 2 (단계별) |
|------|----------------|----------------|
| **소요 시간** | 5-10분 | 20-40분 |
| **난이도** | ⭐ 쉬움 | ⭐⭐⭐ 중간 |
| **제어 수준** | 낮음 | 높음 |
| **품질 제어** | 자동 | 수동 + 자동 |
| **학습 효과** | 낮음 | 높음 |
| **반복 개선** | 전체 재실행 | 특정 Phase만 재실행 |
| **최종 품질** | 85% (평균) | 90% (목표 달성 시) |
| **적합한 경우** | 프로토타입, 학습 | 프로덕션, 고품질 |

### 시나리오별 추천

#### 시나리오 1: "CAAS를 처음 써봅니다"

```bash
caas generate "간단한 요구사항" --verbosity verbose
```
**이유**: 전체 프로세스를 빠르게 경험

#### 시나리오 2: "빠른 프로토타입이 필요합니다"
→ **방법 1 (자동화)** 추천
```bash
caas generate "요구사항" --output ./prototype
```
**이유**: 빠른 반복 개발

#### 시나리오 3: "프로덕션에 배포할 코드입니다"
→ **방법 2 (단계별)** 추천
```bash
# 각 Phase를 순차 실행하며 검증
caas generate-phase --phase 0 ...
caas generate-phase --phase 1 ...
...
```
**이유**: 각 단계 검증으로 최종 품질 보장

#### 시나리오 4: "복잡한 멀티 에이전트 시스템입니다"
→ **방법 2 (단계별)** 추천

**이유**: 복잡한 설계는 세밀한 조정 필요

#### 시나리오 5: "기존 설계를 수정하고 싶습니다"
→ **방법 2 (단계별)** + 수동 편집

## 🐛 문제 해결

### 자주 발생하는 문제

#### 문제 1: 구현률이 낮음 (< 70%)

**원인**: 요구사항이 모호하거나 도메인 미스매치

**해결**:
```bash
# 1. 요구사항 갭 분석
caas analyze-gaps "원래 요구사항"

# 2. 자동 확장
caas expand "원래 요구사항" --output expanded.txt

# 3. 확장된 요구사항으로 재생성
caas generate "$(cat expanded.txt)" --domain [적절한도메인]
```

#### 문제 2: Completeness < 80%

**원인**: Agent/Task 설계 불완전

**해결**:
```bash
# 자동 수정
caas fix --level 3 \
  --agents ./design/agents.json \
  --tasks ./design/tasks.json \
  --golden-data ./artifacts/golden_data.json \
  --output ./design_fixed/

# 수정 결과 확인
diff design/agents.json design_fixed/agents.json
```

#### 문제 3: 코드 실행 오류

**원인**: tools.py 누락 또는 Agent 파라미터 오류

**해결**:

**v0.2.0+**: 자동 수정됨 (재생성만 하면 됨)

**v0.1.x**: 수동 수정 필요
```python
# agents.py 수정
# ❌ 제거
Agent(
    id='agent_name',  # 제거
    tools=['string'],  # tools=[] 로 변경
    memory=True,      # 제거
)

# ✅ 수정 후
Agent(
    tools=[],
)
```

#### 문제 4: Phase가 중간에 실패

**원인**: API 키 오류, 네트워크 문제, API 할당량 초과

**해결**:
```bash
# 1. API 키 확인
cat .env | grep API_KEY

# 2. 네트워크 확인
ping api.openai.com

# 3. 로그 확인
caas generate ... --verbosity debug 2> error.log
cat error.log

# 4. 실패한 Phase부터 재시작
caas generate-phase --phase [실패한Phase번호] ...
```

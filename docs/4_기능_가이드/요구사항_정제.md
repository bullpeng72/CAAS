## 개요

### 문제 정의

기존 CAAS는 "완전한 요구사항"을 기대했지만, 실제 사용자는 **짧고 불충분한 요구사항**을 제공하는 경우가 많습니다.

**Before (기존)**:
```
User: "할일 관리 앱 만들어줘"
CAAS: → 기본적인 CRUD만 생성 (많은 기능 누락)
```

**After (개선)**:
```
User: "할일 관리 앱 만들어줘"
CAAS: → Gap Analysis
      → Auto-Expansion (자동 확장)
      → Interactive Questions (대화형 질문)
      → Traceability Matrix (추적성)
      → TDD (테스트 우선 개발)
      → 완전하고 검증된 코드 생성
```

### 주요 기능

| 기능 | 설명 | 모듈 |
|------|------|------|
| **Gap Analysis** | 누락된 요구사항 자동 탐지 | `caas_framework.refinement.gap_analyzer` |
| **Auto-Expansion** | 자동 요구사항 확장 | `caas_framework.refinement.expander` |
| **Interactive Questions** | 사용자 대화형 질문 생성 | `caas_framework.refinement.question_generator` |
| **Traceability Matrix** | 요구사항-코드 추적 | `caas_framework.validation.traceability` |
| **Test Scenario Generation** | BDD 테스트 시나리오 생성 | `caas_framework.testing.test_scenario` |
| **Test-First Code Gen** | Pytest 테스트 코드 생성 | `caas_framework.testing.test_generator` |
| **Test Execution** | 테스트 자동 실행 및 분석 | `caas_framework.testing.test_executor` |

## Step 1: 요구사항 정제

### 1.1 Gap Analysis (갭 분석)

**목적**: 누락되거나 불충분한 요구사항 항목 자동 탐지

#### 사용법

```python
from caas_framework.refinement import RequirementGapAnalyzer
from caas_framework.models.specifications import ConcretizedRequirement

# Analyzer 생성
analyzer = RequirementGapAnalyzer()

# Gap Analysis 수행
gap_result = analyzer.analyze_gaps(
    requirement="할일 관리 앱 만들어줘",
    concretized=concretized_requirement
)

# 결과 확인
print(f"전체 갭: {gap_result.total_gaps}개")
print(f"Critical: {gap_result.critical_gaps}개")
print(f"완성도: {gap_result.completeness_score:.1%}")

for gap in gap_result.gaps:
    print(f"[{gap.severity}] {gap.description}")
    if gap.suggestions:
        print(f"  제안: {gap.suggestions}")
```

#### 탐지되는 갭 타입

| 갭 타입 | 설명 | 심각도 |
|--------|------|--------|
| `MISSING_NFR` | 비기능 요구사항 누락 | High |
| `MISSING_DATA_MODEL` | 데이터 모델 미정의 | Critical |
| `MISSING_UI_SPEC` | UI 명세 부족 | Medium |
| `MISSING_ACCEPTANCE` | 인수 기준 부재 | Medium |
| `MISSING_SECURITY` | 보안 요구사항 누락 | High |
| `MISSING_ERROR_HANDLING` | 에러 처리 미정의 | Medium |

### 1.2 Auto-Expansion (자동 확장)

**목적**: 자동 수정 가능한 갭을 LLM 또는 휴리스틱으로 채움

#### 사용법

```python
from caas_framework.refinement import RequirementExpander

# Expander 생성 (LLM 선택적)
expander = RequirementExpander(llm_client=your_llm_client)

# 자동 확장
expanded = expander.expand_requirement(
    requirement="할일 관리 앱 만들어줘",
    concretized=concretized_requirement,
    gaps=gap_result.gaps
)

# 결과
print(f"자동 추가된 데이터 모델: {len(expanded.auto_expanded_data_models)}")
print(f"모범 사례 제안: {len(expanded.best_practices)}")
print(f"남은 갭 (수동 입력 필요): {len(expanded.remaining_gaps)}")
```

#### 자동 확장 항목

- **데이터 모델**: 기능에서 엔티티 추론
- **UI 컴포넌트**: 도메인별 표준 UI 추가
- **인수 기준**: BDD 형식으로 생성
- **NFR**: 도메인별 기본값 적용

### 1.3 Interactive Questions (인터랙티브 질문)

**목적**: 수동 입력이 필요한 갭에 대해 사용자 친화적 질문 생성

#### 사용법

```python
from caas_framework.refinement import InteractiveQuestionGenerator

# Question Generator 생성
generator = InteractiveQuestionGenerator()

# 질문 생성
questions = generator.generate_questions(
    gaps=gap_result.gaps,
    domain="TASK_MANAGEMENT"
)

# 질문 표시 (Streamlit/CLI/Web UI)
for question in questions:
    if question.question_type == "SINGLE_CHOICE":
        answer = ask_user(question.question_text, question.options)
    elif question.question_type == "YES_NO":
        answer = ask_yes_no(question.question_text)
```

#### 질문 타입

| 타입 | 설명 | 예시 |
|------|------|------|
| `SINGLE_CHOICE` | 단일 선택 | "예상 동시 사용자 수는?" |
| `MULTI_CHOICE` | 복수 선택 | "알림 채널 선택" |
| `YES_NO` | 예/아니오 | "로그인이 필요한가요?" |
| `TEXT_INPUT` | 텍스트 입력 | "프로젝트 설명 입력" |
| `NUMBER_INPUT` | 숫자 입력 | "최대 할일 개수" |

## Step 2: 추적성 강화

### 2.1 Traceability Matrix (추적성 매트릭스)

**목적**: Requirement → Feature → Agent → Task → Code의 전체 추적 경로 구축

#### 사용법

```python
from caas_framework.validation.traceability import TraceabilityManager

# Manager 생성
trace_manager = TraceabilityManager()

# Traceability 구축
trace_manager.build_from_workflow(
    requirement="할일 관리 앱",
    golden_data=concretized_requirement,
    agents=agent_specs,
    tasks=task_specs,
    generated_code={"main.py": code_content}
)

# 커버리지 검증
coverage = trace_manager.matrix.validate_completeness()
print(f"전체 커버리지: {coverage.coverage_percentage:.1f}%")
print(f"미구현 항목: {len(coverage.gaps)}")

# 리포트 생성
report = trace_manager.generate_report()
print(report)
```

#### 추적 링크 타입

```
Requirement
    ↓ (derives_from)
Feature
    ↓ (implements)
Task
    ↓ (assigned_to)
Agent
    ↓ (generates)
Code
```

### 2.2 전방/후방 추적

```python
# 전방 추적: Requirement → Code
forward_links = trace_manager.matrix.get_trace_forward("requirement", "REQ-001")

# 후방 추적: Code → Requirement
backward_links = trace_manager.matrix.get_trace_backward("code", "create_task")

# 전체 경로
full_paths = trace_manager.matrix.get_full_trace_path("requirement", "REQ-001")
```

## Step 3: TDD 통합

### 3.1 Test Scenario Generation (테스트 시나리오 생성)

**목적**: Feature의 Acceptance Criteria를 BDD 테스트 시나리오로 변환

#### 사용법

```python
from caas_framework.testing import TestScenarioGenerator

# Generator 생성
scenario_gen = TestScenarioGenerator(llm_client=llm_client)

# 시나리오 생성
test_scenarios = scenario_gen.generate_scenarios(
    features=concretized_requirement.features
)

# 결과 확인
for scenario in test_scenarios:
    print(f"Scenario: {scenario.scenario_id}")
    print(f"  Given: {scenario.bdd.given}")
    print(f"  When:  {scenario.bdd.when}")
    print(f"  Then:  {scenario.bdd.then}")
```

#### BDD 시나리오 예시

```
Scenario: 할일 생성 테스트
  Given: 사용자가 로그인되어 있다
    And: 할일 생성 페이지에 접속한다
  When:  제목에 "프로젝트 완료"를 입력한다
    And: 생성 버튼을 클릭한다
  Then:  새 할일이 목록에 표시된다
    And: 성공 메시지가 표시된다
```

### 3.2 Test Code Generation (테스트 코드 생성)

**목적**: BDD 시나리오를 Pytest 코드로 변환

#### 사용법

```python
from caas_framework.testing import TestFirstGenerator

# Generator 생성
test_gen = TestFirstGenerator()

# 테스트 코드 생성
test_code_result = test_gen.generate_test_code(
    scenarios=test_scenarios,
    entity_name="Task",
    framework="pytest"
)

# 생성된 코드 확인
print(test_code_result.test_code)
```

#### 생성되는 Pytest 코드

```python
import pytest
from backend.crud import create_task, get_task
from backend.schemas import TaskCreate

def test_create_task(db):
    """Test: 할일 생성"""
    # Arrange
    # Given: 사용자가 로그인되어 있다
    task_data = TaskCreate(title="프로젝트 완료", description="...")

    # Act
    # When: 생성 버튼을 클릭한다
    task = create_task(db, task_data)

    # Assert
    # Then: 새 할일이 목록에 표시된다
    assert task.id is not None
    assert task.title == "프로젝트 완료"
```

### 3.3 Test Execution (테스트 실행)

**목적**: 생성된 테스트를 자동으로 실행하고 결과 분석

#### 사용법

```python
from caas_framework.testing import TestExecutor

# Executor 생성
executor = TestExecutor()

# 테스트 실행
test_result = executor.execute_pytest(
    test_file_path="tests/test_task.py",
    test_code=test_code_result.test_code,
    coverage=True
)

# 결과 확인
print(f"전체: {test_result.total_tests}")
print(f"통과: {test_result.passed}")
print(f"실패: {test_result.failed}")
print(f"커버리지: {test_result.coverage_percentage:.1f}%")
```

## 통합 워크플로우

### End-to-End 예시

```python
# 1. 짧은 요구사항 입력
requirement = "할일 관리 앱 만들어줘"

# 2. Gap Analysis
analyzer = RequirementGapAnalyzer()
gaps = analyzer.analyze_gaps(requirement, concretized)

# 3. Auto-Expansion
expander = RequirementExpander(llm_client)
expanded = expander.expand_requirement(requirement, concretized, gaps.gaps)

# 4. Interactive Questions (옵션)
if expanded.remaining_gaps:
    question_gen = InteractiveQuestionGenerator()
    questions = question_gen.generate_questions(expanded.remaining_gaps, domain)
    # 사용자에게 질문 표시...

# 5. Traceability 구축
trace_manager = TraceabilityManager()
trace_manager.build_from_workflow(requirement, golden_data, agents, tasks)

# 6. Test Scenario 생성
scenario_gen = TestScenarioGenerator(llm_client)
test_scenarios = scenario_gen.generate_scenarios(golden_data.features)

# 7. Test Code 생성
test_gen = TestFirstGenerator()
test_code = test_gen.generate_test_code(test_scenarios, "Task")

# 8. Test 실행
executor = TestExecutor()
test_result = executor.execute_pytest(test_code.test_file_path, test_code.test_code)

# 9. 검증 및 리포트
coverage_report = trace_manager.matrix.validate_completeness()
print(f"요구사항 커버리지: {coverage_report.coverage_percentage:.1f}%")
print(f"테스트 통과율: {test_result.passed / test_result.total_tests * 100:.1f}%")
```

## API 레퍼런스

### Gap Analysis

```python
class RequirementGapAnalyzer:
    def __init__(self, llm_client=None, domain_checklists_path=None): ...
    def analyze_gaps(self, requirement: str, concretized: ConcretizedRequirement) -> GapAnalysisResult: ...

class GapAnalysisResult(BaseModel):
    total_gaps: int
    critical_gaps: int
    high_gaps: int
    medium_gaps: int
    low_gaps: int
    auto_fixable_gaps: int
    gaps: List[RequirementGap]
    completeness_score: float  # 0.0 ~ 1.0
```

### Traceability

```python
class TraceabilityManager:
    def build_from_workflow(self, requirement, golden_data, agents, tasks, generated_code=None): ...
    def generate_report(self) -> str: ...
    def export_to_json(self) -> Dict: ...

class TraceabilityMatrix:
    def add_link(self, source_type, source_id, target_type, target_id, ...): ...
    def get_trace_forward(self, source_type, source_id) -> List[TraceabilityLink]: ...
    def get_trace_backward(self, target_type, target_id) -> List[TraceabilityLink]: ...
    def validate_completeness(self) -> CoverageReport: ...
```

### TDD

```python
class TestScenarioGenerator:
    def generate_scenarios(self, features: List[FeatureSpec]) -> List[TestScenario]: ...

class TestFirstGenerator:
    def generate_test_code(self, scenarios, entity_name, framework="pytest") -> TestCodeResult: ...

class TestExecutor:
    def execute_pytest(self, test_file_path, test_code, coverage=True) -> TestResult: ...
```

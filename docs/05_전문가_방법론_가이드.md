### 1.4 3-Level Auto-Fixing System

CAAS는 LLM이 생성한 코드의 일반적인 오류를 3단계로 자동 수정합니다.

#### 3-Level 전략

```
Level 1: Template-based Fix
  ├─ 속도: ⚡⚡⚡ (즉시)
  ├─ 정확도: ⭐⭐⭐
  ├─ 비용: 무료
  └─ 사용 사례: 간단한 패턴 수정 (id= 제거, tools=[] 변환)

Level 2: Rule-based Fix
  ├─ 속도: ⚡⚡ (빠름)
  ├─ 정확도: ⭐⭐⭐⭐
  ├─ 비용: 무료
  └─ 사용 사례: 복잡한 패턴 매칭 (import 추가, 의존성 해결)

Level 3: LLM-based Fix ⭐ (가장 강력)
  ├─ 속도: ⚡ (느림)
  ├─ 정확도: ⭐⭐⭐⭐⭐
  ├─ 비용: LLM API 호출
  └─ 사용 사례: 복잡한 로직 수정, 구조 변경
```

#### 구현된 5가지 Auto-Fix

**Fix #1: Remove 'id=' parameter** (Level 1)
```python
# ❌ Before
agent = Agent(id="agent1", role="researcher", ...)

# ✅ After
agent = Agent(role="researcher", ...)
```

**Fix #2: Convert tools=['string'] to tools=[]** (Level 1)
```python
# ❌ Before
agent = Agent(role="...", tools=["search_tool"], ...)

# ✅ After
agent = Agent(role="...", tools=[search_tool], ...)
```

**Fix #3: Generate tools.py if missing** (Level 2)
- tools.py가 없으면 자동 생성 (stub 포함)
- 3-Layer Defense: Validation → LLM Generation → Fallback

**Fix #4: Ensure tools.py import** (Level 2)
```python
# agents.py에 자동 추가
from tools import search_tool, scrape_tool
```

**Fix #5: Add manager_llm for hierarchical process** (Level 2) ⭐ NEW
```python
# ❌ Before (ValidationError 발생)
crew = Crew(
    agents=[...],
    tasks=[...],
    process=Process.hierarchical,
    verbose=True
)

# ✅ After (자동 수정)
from langchain_openai import ChatOpenAI

manager_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.1)

crew = Crew(
    agents=[...],
    tasks=[...],
    process=Process.hierarchical,
    manager_llm=manager_llm,  # 자동 추가
    verbose=True
)
```

**적용 위치**: `caas_framework/agents/code_generator.py:352-555`

#### Auto-Fix 실행 방법

**1. 자동 실행** (코드 생성 시 기본 적용)
```bash
caas generate "요구사항" --output ./project
# Auto-Fix가 자동으로 적용됨
```

**2. 수동 실행** (기존 코드 수정)
```bash
# Level 1-2 수정 (빠름, 무료)
caas fix --level 2 \
  --agents ./artifacts/agents.json \
  --tasks ./artifacts/tasks.json \
  --output ./fixed

# Level 3 수정 (느림, LLM 사용)
caas fix --level 3 \
  --agents ./artifacts/agents.json \
  --tasks ./artifacts/tasks.json \
  --output ./fixed
```

## 2장: 핵심 방법론과 CAAS 접목

### 2.1 BMAD 6-Phase 방법론

**BMAD** (Build-Measure-Analyze-Deploy)는 CAAS의 핵심 워크플로우입니다. 6개의 Phase로 구성되어 요구사항부터 프로덕션 코드까지 체계적으로 생성합니다.

#### BMAD 철학

1. **단계적 구체화** (Incremental Refinement)
   - 각 Phase는 이전 Phase의 산출물을 입력으로 받아 점진적으로 구체화
   - Phase 0: 모호한 요구사항 → Phase 5: 실행 가능한 코드

2. **검증 가능성** (Verifiability)
   - 각 Phase마다 명확한 산출물 (Artifacts) 생성
   - 산출물을 통해 진행 상황 추적 및 검증 가능

3. **추적성** (Traceability)
   - 요구사항 → 아키텍처 → 설계 → 코드의 추적 매트릭스
   - 모든 코드가 어떤 요구사항에서 비롯되었는지 추적 가능

4. **반복 가능성** (Repeatability)
   - 각 Phase를 독립적으로 재실행 가능
   - 실패한 Phase만 재실행하여 효율성 확보

#### Phase 상세 설명

**Phase 0: Concretization (요구사항 구체화)**

```
입력: 자연어 요구사항 (모호함 허용)
처리: RequirementConcretizer + HierarchicalFeatureExtractor
출력: Golden Data (ConcretizedRequirement)
```

### 2.2 Spec-Driven Development (SDD)

**SDD**는 "명세 우선, 코드는 나중"이라는 철학입니다. CAAS는 SDD를 완전히 채택하여 구현했습니다.

#### SDD 원칙

1. **Complete Specification First**
   - 코드 작성 전에 완전한 명세 작성
   - Golden Data = 완전하고 명확한 명세

2. **Unambiguous Requirements**
   - 모호한 요구사항을 구조화된 데이터로 변환
   - LLM이 해석 가능한 형식

3. **Traceable Implementation**
   - 명세 → 코드의 명확한 추적 경로
   - 모든 코드가 명세에서 유래

#### CAAS의 SDD 구현

**1. Golden Data = Spec**

Golden Data는 CAAS의 중심 명세입니다. 모든 Phase가 이를 기반으로 동작합니다.

```
요구사항 (자연어)
  ↓ Phase 0
Golden Data (구조화된 명세)
  ↓ Phase 1-4
Agent/Task Specs (실행 명세)
  ↓ Phase 5
Production Code (구현)
```

**2. Boundaries Spec (보안 명세)**

```python
# Golden Data의 필수 요소
boundaries: BoundariesSpec
  - always_allowed: ["읽기 작업", "기본 CRUD", "로깅"]
  - ask_first: ["파일 작업", "API 호출", "DB 변경"]
  - never_allowed: ["rm -rf", "임의 코드 실행", "시스템 명령"]
```

이 명세를 통해 생성되는 에이전트가 절대 위험한 작업을 수행하지 않도록 보장합니다.

**3. Commands Spec (실행 명세)**

```python
commands: CommandsSpec
  - install: "pip install -r requirements.txt"
  - test: "pytest tests/"
  - run: "python main.py"
  - lint: "pylint src/"
  - format: "black src/"
  - build: "docker build -t myapp ."  # 선택적
  - deploy: "kubectl apply -f k8s/"    # 선택적
```

개발자가 프로젝트를 어떻게 실행할지 명확히 명시합니다.

**4. Code Style Spec (코드 품질 명세)**

```python
code_style: CodeStyleSpec
  - formatter: "black"              # black, autopep8, yapf
  - line_length: 88                 # 기본 88
  - use_type_hints: True            # 타입 힌트 사용
  - docstring_style: "google"       # google, numpy, sphinx
  - import_order: "isort"           # isort profile
```

일관된 코드 스타일을 보장합니다.

**5. Git Workflow Spec (협업 명세)**

```python
git_workflow: GitWorkflowSpec
  - branch_naming: "feature/{issue-number}-{description}"
  - commit_message_format: "<type>(<scope>): <subject>"
  - requires_pr: True
  - main_branch: "main"
```

팀 협업 규칙을 명세에 포함합니다.

#### SDD 워크플로우

**Step 1: 명세 작성 (Phase 0)**
```bash
caas generate-phase --phase 0 "요구사항" --output ./specs
# artifacts/golden_data.json 생성
```

**Step 2: 명세 검토 및 수정**

```bash

```

**Step 4: 명세 기반 코드 생성**

#### SDD의 장점

1. **예측 가능성**: 명세가 명확하면 결과물도 예측 가능
2. **검증 가능성**: 명세와 코드를 비교하여 완전성 검증
3. **반복 가능성**: 동일한 명세로 일관된 코드 생성
4. **유지보수성**: 명세 수정 후 재생성으로 일관성 유지

### 2.4 Domain-Driven Design (DDD)

CAAS는 Domain 중심으로 설계되었습니다. 도메인에 따라 최적화된 Agent, Task, Tool을 자동 생성합니다.

#### DDD 핵심 개념

**1. Domain Types (도메인 타입)**

8가지 도메인을 지원하며, 각 도메인마다 최적화된 전략을 사용합니다.

```python
# caas_framework/models/domain_types.py

class DomainType(str, Enum):
    CONVERSATIONAL_AI        # 대화형 AI (챗봇, 비서)
    CONTENT_CREATION         # 콘텐츠 생성 (블로그, 리포트)
    DATA_ANALYSIS           # 데이터 분석 (통계, 시각화)
    WORKFLOW_AUTOMATION     # 워크플로우 자동화
    TASK_MANAGEMENT         # 태스크 관리 (Todo, 프로젝트)
    E_COMMERCE              # 이커머스 (쇼핑몰)
    PROJECT_MANAGEMENT      # 프로젝트 관리
    CUSTOMER_SUPPORT        # 고객 지원 (헬프데스크)
```

**2. Execution Patterns (실행 패턴)**

도메인에 따라 3가지 실행 패턴 중 하나를 선택합니다.

```python
class ExecutionPattern(str, Enum):
    AGENT_BASED = "AGENT_BASED"      # Multi-agent 협업 (추천)
    CRUD_BASED = "CRUD_BASED"        # CRUD 중심 (데이터 관리)
    HYBRID = "HYBRID"                # 혼합형
```

**패턴별 특징**:
| 패턴 | 사용 도메인 | Agent 수 | 구현률 |
|------|------------|----------|--------|
| AGENT_BASED | CONVERSATIONAL_AI, CONTENT_CREATION, CUSTOMER_SUPPORT | 3-5개 | 98.7% ⭐ |
| HYBRID | DATA_ANALYSIS, WORKFLOW_AUTOMATION | 2-4개 | 98.3% |
| CRUD_BASED | TASK_MANAGEMENT, E_COMMERCE, PROJECT_MANAGEMENT | 1-2개 | 중간 |

**3. Domain-Specific Agents**

각 도메인에 최적화된 Agent 패턴이 있습니다.

```python
# data/ontology/agent_patterns.json

{
```

```python
# caas_framework/bmad/feature_extraction.py

class HierarchicalFeatureExtractor:
    async def extract_complete_features(
        self, requirement: str, domain: str
    ) -> List[FeatureSpec]:
        # Level 1: Top-level features (주요 기능)
        top_features = await self._extract_top_level_features(requirement)

        # Level 2: Sub-features (하위 기능)
        all_features = []
        for feature in top_features:
            sub_features = await self._extract_sub_features(feature, domain)
            all_features.extend([feature] + sub_features)

        return all_features
```

**Fix 1: Task 의존성 순환 참조 제거**
```python
# caas_framework/fixing/auto_fixer.py

def fix_circular_dependencies(tasks: List[TaskSpecModel]) -> List[TaskSpecModel]:
    # Build dependency graph
    graph = {}
    for task in tasks:
        graph[task.id] = task.context  # context = dependencies

    # Detect cycles
    cycles = detect_cycles(graph)

    # Remove weakest dependencies to break cycles
    for cycle in cycles:
        weakest_edge = find_weakest_edge_in_cycle(cycle, tasks)
        # Remove dependency
        for task in tasks:
            if task.id == weakest_edge[0]:
                if weakest_edge[1] in task.context:
                    task.context.remove(weakest_edge[1])
                    logger.info(f"[AutoFix] Removed circular dependency: {weakest_edge}")

    return tasks
```

**Fix 2: Missing Agent 자동 생성**
```python
def fix_missing_agents(
    agents: List[AgentSpecModel],
    tasks: List[TaskSpecModel]
) -> List[AgentSpecModel]:
    # Find tasks without assigned agents
    agent_ids = set(a.id for a in agents)
    required_agents = set(t.agent for t in tasks)
    missing_agents = required_agents - agent_ids

    # Create missing agents
    for agent_id in missing_agents:
        # Infer role from agent_id
        role = agent_id.replace("_agent", "").replace("_", " ")
        new_agent = AgentSpecModel(
            id=agent_id,
            role=role,
            goal=f"{role} 작업 수행",
            backstory=f"{role} 전문가",
            tools=[],
            allow_delegation=False
        )
        agents.append(new_agent)
        logger.info(f"[AutoFix] Created missing agent: {agent_id}")

    return agents
```

```python
def fix_agent_tools(agents: List[AgentSpecModel]) -> List[AgentSpecModel]:
```

```python
        verbose=True
    )
    result = crew.kickoff(inputs=user_inputs)
    return result

# Hierarchical Process Template (requires manager_llm)
def main():
    agents = create_agents()
    tasks = create_tasks(agents)

    manager_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.1)

    crew = Crew(
        agents=list(agents.values()),
        tasks=tasks,
        process=Process.hierarchical,
        manager_llm=manager_llm,  # 필수!
        verbose=True
    )
    result = crew.kickoff(inputs=user_inputs)
    return result
```

```python
def generate_tools_py(tool_names: List[str]) -> str:
    # Layer 1: Validation (도구명 검증 및 번역)
    validated_tools = []
    for tool_name in tool_names:
        if tool_name in KOREAN_TO_ENGLISH_TOOL_MAP:
            tool_name = KOREAN_TO_ENGLISH_TOOL_MAP[tool_name]  # 한→영 변환
        validated_tools.append(tool_name)

    # Layer 2: LLM Generation (실제 구현 생성)
    try:
        tools_code = llm_generate_tools(validated_tools)
        # BaseTool 상속, _run() 메서드 구현, 에러 핸들링 포함
        return tools_code
    except Exception as e:
        logger.warning(f"LLM generation failed: {e}, falling back to stub")

    # Layer 3: Fallback (100% 실행 가능한 Stub)
    stub_code = generate_tool_stubs(validated_tools)
    # 각 Tool에 대해 기본 구현 생성
    return stub_code
```

```python
# caas_framework/agents/code_generator.py:352-555

def _autofix_generated_code(self, files: Dict[str, str]) -> Dict[str, str]:
    """
    5가지 Auto-Fix 적용

    Fix #1: Remove 'id=' parameter from Agent()
    Fix #2: Convert tools=['string'] to tools=[]
    Fix #3: Generate tools.py if missing
    Fix #4: Ensure tools.py import in agents.py
    Fix #5: Add manager_llm for hierarchical process ⭐ NEW
    """

    # Fix #1: 'id=' 파라미터 제거 (Level 1)
    for file_path in ["agents.py", "src/agents.py"]:
        if file_path in files:
            code = files[file_path]
            code = re.sub(r"id=['\"].*?['\"]\s*,\s*", "", code)
            files[file_path] = code

    # Fix #2: tools=['string'] → tools=[] 변환 (Level 1)
    for file_path in ["agents.py", "src/agents.py"]:
        if file_path in files:
            code = files[file_path]
            code = re.sub(
                r"tools=\[(.*?)\]",
                lambda m: f"tools=[{', '.join([t.strip().strip('\"').strip(\"'\") for t in m.group(1).split(',') if t.strip()])}]",
                code
            )
            files[file_path] = code

    # Fix #3: tools.py 생성 (Level 2)
    if "tools.py" not in files and "src/tools.py" not in files:
        # 3-Layer Defense 사용하여 tools.py 생성
        tools_code = generate_tools_py_with_3_layer_defense(agents)
        files["tools.py"] = tools_code
        logger.info("[AutoFix] Generated missing tools.py")

    # Fix #4: tools.py import 추가 (Level 2)
    for file_path in ["agents.py", "src/agents.py"]:
        if file_path in files:
            code = files[file_path]
            if "from tools import" not in code:
                # 필요한 tool import 자동 추가
                tool_imports = extract_tool_names(code)
                import_line = f"from tools import {', '.join(tool_imports)}\n"
                code = add_import_after_crewai(code, import_line)
                files[file_path] = code
                logger.info("[AutoFix] Added tools import to agents.py")

    # Fix #5: manager_llm for hierarchical process (Level 2) ⭐ NEW
    if "main.py" in files:
        main_code = files["main.py"]

        if "Process.hierarchical" in main_code and "manager_llm" not in main_code:
            # 1. langchain_openai import 추가
            if "from langchain_openai import ChatOpenAI" not in main_code:
                import_match = re.search(r"(from crewai import .*?\n)", main_code)
                if import_match:
                    import_line = import_match.group(1)
                    main_code = main_code.replace(
                        import_line,
                        import_line + "from langchain_openai import ChatOpenAI\n"
                    )

            # 2. manager_llm 초기화 추가
            crew_match = re.search(r"(\s+)(crew\s*=\s*Crew\()", main_code, re.MULTILINE)
            if crew_match:
                indent = crew_match.group(1)
                crew_start = crew_match.group(2)
                manager_llm_code = f"""{indent}# Manager LLM for hierarchical process
{indent}manager_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.1)

{indent}"""
                main_code = main_code.replace(indent + crew_start, manager_llm_code + crew_start)

            # 3. manager_llm 파라미터 추가
            main_code = re.sub(
                r"(process=Process\.hierarchical),(\s*)",
                r"\1,\2manager_llm=manager_llm,\2",
                main_code
            )

            files["main.py"] = main_code
            logger.info("[AutoFix] Added manager_llm for hierarchical process")

    return files
```

#### `caas fix`

검증에서 발견된 이슈를 3-Level Auto-Fix로 자동 수정합니다.

```bash
caas fix [OPTIONS]
```

**옵션**:
- `--level LEVEL`: Fix 레벨 (1: Template, 2: Rule, 3: LLM) 기본: 2
- `--agents PATH`: Agents JSON 파일
- `--tasks PATH`: Tasks JSON 파일
- `--golden-data PATH`: Golden Data 파일
- `--code PATH`: 생성된 코드 디렉토리
- `--output PATH` / `-o PATH`: 수정된 파일 출력 디렉토리
- `--validation-report PATH`: 검증 리포트 파일 (validate 출력)

**사용 예시**:
```bash
# Level 2 수정 (Rule-based, 빠르고 무료)
caas fix --level 2 \
  --agents ./artifacts/agents.json \
  --tasks ./artifacts/tasks.json \
  --output ./fixed

# Level 3 수정 (LLM-based, 강력하지만 느림)
caas fix --level 3 \
  --agents ./artifacts/agents.json \
  --tasks ./artifacts/tasks.json \
  --output ./fixed

# 검증 리포트 기반 수정
caas fix --level 3 \
  --validation-report ./validation_report.json \
  --agents ./artifacts/agents.json \
  --tasks ./artifacts/tasks.json \
  --output ./fixed

# 코드 수정 (생성된 코드)
caas fix --level 2 \
  --code ./project \
  --output ./project-fixed
```

**수정 가능한 이슈**:
- **Level 1**: 간단한 패턴 (id= 제거, tools=[] 변환)
- **Level 2**: 복잡한 패턴 (순환 참조 제거, import 추가, manager_llm 추가)
- **Level 3**: LLM 기반 (로직 수정, 구조 변경)

```python
# services/agent_service.py

import sys
sys.path.append("./agents-core")

from agents import create_agents
from tasks import create_tasks
from crewai import Crew, Process

class AgentService:
    """
    CAAS 생성 Agent를 래핑하여 비즈니스 로직에서 사용
    """

    def __init__(self):
        self.agents = create_agents()
        self.tasks = create_tasks(self.agents)
        self.crew = Crew(
            agents=list(self.agents.values()),
            tasks=self.tasks,
            process=Process.sequential,
            verbose=False  # Production에서는 verbose=False
        )

    def generate_article(self, topic: str, keywords: List[str]) -> dict:
        """
        블로그 글 생성 (Agent 실행)

        Args:
            topic: 주제
            keywords: 키워드 리스트

        Returns:
            {
                "title": "...",
                "content": "...",
                "meta": {...}
            }
        """
        # Agent 실행
        result = self.crew.kickoff(inputs={
            "topic": topic,
            "keywords": ", ".join(keywords)
        })

        # 결과 파싱 (Agent 출력은 문자열)
        article = self._parse_result(result)

        return article

    def _parse_result(self, result: str) -> dict:
        """Agent 결과를 파싱하여 구조화된 데이터로 변환"""
        # TODO: LLM 출력을 파싱하여 dict로 변환
        return {"title": "...", "content": result, "meta": {}}

# Singleton 인스턴스
agent_service = AgentService()
```

```bash
while true; do

    --agents ./phase3/artifacts/agents.json \

    --golden-data ./artifacts/golden_data.json

  # 3. 검증 실패 시 자동 수정
  if [ $? -ne 0 ]; then
    caas fix --level 3 \
      --agents ./phase3/artifacts/agents.json \
      --tasks ./phase3/artifacts/tasks.json \
      --output ./phase3-fixed

    # 4. 재검증
    caas validate --validator all \
      --agents ./phase3-fixed/agents.json \
      --tasks ./phase3-fixed/tasks.json

    if [ $? -eq 0 ]; then
      echo "✅ Validation passed after auto-fix"
      break
    fi
  else
    echo "✅ Validation passed"
```

#### 케이스 3: 멀티 Agent 협업 시스템 (계층적 관리)

**요구사항**:
- 프로젝트 관리 Agent (Manager)
- 개발 Agent (Worker)
- 테스트 Agent (Worker)
- 배포 Agent (Worker)
- 모니터링 Agent (Worker)

**전략**: Hierarchical Process + Manager Agent

```bash
# Hierarchical 워크플로우 생성
caas generate "프로젝트 자동화 시스템 - Manager가 Worker 관리" \
  --domain WORKFLOW_AUTOMATION \
  --workflow hierarchical \
  --output ./project-automation

# 주요 산출물:
# - main.py (with manager_llm)
# - agents.py (5 agents)
# - tasks.py (dynamic task allocation)
```

**생성된 main.py**:
```python
from crewai import Crew, Process
from langchain_openai import ChatOpenAI
from agents import create_agents
from tasks import create_tasks

def main():
    agents = create_agents()
    tasks = create_tasks(agents)

    # Manager LLM (Hierarchical Process 필수)
    manager_llm = ChatOpenAI(model="gpt-4o", temperature=0.1)

    crew = Crew(
        agents=list(agents.values()),
        tasks=tasks,
        process=Process.hierarchical,  # ← Hierarchical
        manager_llm=manager_llm,       # ← Fix #5 자동 적용
        verbose=True
    )

    result = crew.kickoff(inputs={"project": "New Feature X"})
    return result
```

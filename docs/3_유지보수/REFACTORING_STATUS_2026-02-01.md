## 🔄 전략 변경 이유

### 원래 계획
Phase 1 → Phase 2 (P2.1, P2.2, P2.3) → Phase 3 → Phase 4

### 새로운 계획
Phase 1 → P2.1 → **Phase 3** → P2.2/P2.3 → Phase 4

### 변경 이유
1. **P2.2가 예상보다 훨씬 복잡함**
   - Sync vs Async 아키텍처 차이
   - 광범위한 의존성
   - 높은 리스크

2. **Phase 3가 더 효율적**
   - 간단하고 기계적인 작업
   - 즉각적인 코드 정리 효과
   - 리스크 매우 낮음
   - 빠른 완료 가능 (1주)

3. **점진적 접근이 더 안전**
   - 복잡한 P2.2는 더 많은 준비 필요
   - Phase 3 완료 후 코드베이스가 더 깨끗해짐
   - 그 후 P2.2 진행하면 더 안전

## 개요

CAAS 프레임워크는 자연어 요구사항을 프로덕션 코드로 변환하는 과정에서 네 가지 핵심 지식 체계를 활용합니다.

| 시스템 | 역할 | 위치 |
|--------|------|------|
| **Golden Data 모델** | 자연어를 구조화된 데이터로 변환 (Phase 0 출력) | `caas_framework/methodology/` |
| **도메인 분류 시스템** | 요구사항 성격 분류 → 코드 생성 전략 결정 | `caas_framework/models/`, `caas_framework/codegen/` |
| **온톨로지 시스템** | 도구·에이전트 역할·도메인 개념 정의 | `caas_framework/knowledge/ontology/`, `data/ontology/` |
| **템플릿 시스템** | Jinja2 기반 프로덕션 코드 생성 | `data/templates/` |

---

## 1. 전체 데이터 흐름

```
자연어 요구사항
    │
    ▼ Phase 0: Concretization
┌─────────────────────────────────────┐
│  ConcretizedRequirement (Golden Data)│
│  - FeatureSpec[]                    │
│  - DataModel[]                      │
│  - UIComponent[]                    │
│  - BoundariesSpec                   │
│  - CommandsSpec                     │
│  - CodeStyleSpec / GitWorkflowSpec  │
└─────────────────────────────────────┘
    │
    ├──▶ Domain Ontology (DomainType 분류)
    │         │
    │         ▼
    │    DomainStrategyConfig
    │    (AGENT_BASED / CRUD_BASED / HYBRID)
    │
    ├──▶ Tool Ontology (도구 추천)
    │         │
    │         ▼
    │    ConceptualTool[] → 구체적 구현체
    │
    └──▶ Agent Role Ontology (역할 매핑)
              │
              ▼
         AgentRole × TaskType → ROLE_TASK_MAPPINGS
              │
              ▼
         Jinja2 템플릿 렌더링 (26개 .j2)
              │
              ▼
         프로덕션 코드
         (agents.py, tasks.py, crew.py, main.py, tools.py, tests/, ...)
```

## 2. Golden Data 모델 (ConcretizedRequirement)

**위치**: `caas_framework/methodology/golden_data.py`, `caas_framework/models/specifications.py`

Phase 0 (Concretization)의 출력이자 이후 모든 Phase의 공유 입력 데이터입니다.

### 2.1 최상위 구조

```python
class ConcretizedRequirement(BaseModel):
    project_name: str                    # 프로젝트명
    domain: DomainType                   # 분류된 도메인
    description: str                     # 정제된 요구사항 설명
    features: List[FeatureSpec]          # 기능 명세 목록
    data_models: List[DataModel]         # 데이터 모델 목록
    ui_components: List[UIComponent]     # UI 컴포넌트 (명시적 UI 요청 시만 생성)
    boundaries: BoundariesSpec           # 성능/보안/확장성 제약
    commands: CommandsSpec               # CLI 명령어 정의
    code_style: CodeStyleSpec            # 코딩 컨벤션
    git_workflow: GitWorkflowSpec        # Git 브랜치/커밋 전략
```

### 2.2 FeatureSpec — 기능 명세

```python
class FeatureSpec(BaseModel):
    id: str                              # 기능 고유 ID (예: "F001")
    name: str                            # 기능명 (한국어)
    description: str                     # 상세 설명
    priority: str                        # "HIGH" | "MEDIUM" | "LOW"
    inputs: List[str]                    # 입력 파라미터 목록
    outputs: List[str]                   # 출력 데이터 목록
    dependencies: List[str]              # 의존 기능 ID 목록
    acceptance_criteria: List[str]       # 완료 기준 (TDD 테스트 생성에 활용)
    tools_needed: List[str]              # 필요 도구 힌트
```

**활용**: Phase 1 도메인 분류 기준 → Phase 3 Agent/Task 개수 결정 → Phase 5 TDD 테스트 자동 생성

### 2.3 DataModel — 데이터 모델

```python
class DataModel(BaseModel):
    name: str                            # 모델명 (예: "Task", "User")
    fields: List[FieldSpec]              # 필드 목록
    relationships: List[str]             # 관계 설명 (예: "User has many Tasks")
    storage: str                         # "sqlite" | "postgresql" | "memory" | "file"

class FieldSpec(BaseModel):
    name: str
    type: str                            # Python 타입 힌트
    required: bool
    description: str
```

**활용**: `backend/models.j2` → Pydantic/SQLAlchemy 모델, `backend/api.j2` → FastAPI CRUD

### 2.4 UIComponent — UI 컴포넌트

```python
class UIComponent(BaseModel):
    component_type: str                  # "form" | "dashboard" | "table" | "chart"
    name: str
    fields: List[str]                    # 폼 필드 목록
    actions: List[str]                   # 버튼/액션 목록
    framework: str                       # "streamlit" | "react" | "fastapi"
```

> **주의**: `ui_components`는 요구사항에 명시적인 UI 키워드(`streamlit`, `대시보드`, `웹 UI` 등)가 있을 때만 생성됩니다. 기본값은 빈 리스트(`[]`)입니다. (v0.6.4 버그 수정)

### 2.5 BoundariesSpec — 비기능 요구사항

```python
class BoundariesSpec(BaseModel):
    performance: Dict[str, Any]
    # 예: {"response_time_ms": 200, "throughput_rps": 100, "concurrent_users": 50}
    security: Dict[str, Any]
    # 예: {"authentication": "JWT", "authorization": "RBAC", "data_encryption": true}
    scalability: Dict[str, Any]
    # 예: {"horizontal_scaling": true, "caching": "Redis", "database_sharding": false}
    reliability: Dict[str, Any]
    # 예: {"uptime_sla": "99.9%", "backup_frequency": "daily"}
```

**활용**: `caas_framework/qa/performance_tester.py`의 성능 테스트 기준

### 2.6 CommandsSpec / CodeStyleSpec / GitWorkflowSpec

```python
class CommandsSpec(BaseModel):
    main_command: str                    # 기본 실행 명령어 (예: "python main.py")
    subcommands: List[CommandDef]
    environment_variables: List[str]

class CodeStyleSpec(BaseModel):
    formatter: str                       # "black"
    linter: str                          # "flake8" | "ruff"
    type_checker: str                    # "mypy"
    max_line_length: int                 # 100

class GitWorkflowSpec(BaseModel):
    main_branch: str                     # "main" | "master"
    feature_branch_pattern: str          # "feature/{description}"
    commit_message_format: str           # Conventional Commits
```

### 5.3 OntologyValidator 검증 로직

`caas_framework/validation/ontology_validator.py`가 다음을 자동 검증합니다:

1. **도구 적합성**: Agent에 할당된 도구가 해당 역할의 `ToolType`에 맞는지
2. **작업 유형 일치**: `TaskType`이 `ROLE_TASK_MAPPINGS` 범위 내인지
3. **의존성 순환**: Task 간 순환 의존성(cycle) 탐지
4. **도구 중복**: 동일 도구의 여러 Agent 중복 할당 탐지

```python
class OntologyValidator:
    def validate(self, agents: List[AgentSpec], tasks: List[TaskSpec]) -> ValidationResult:
        issues = []
        issues += self._check_tool_compatibility(agents)
        issues += self._check_task_type_mapping(agents, tasks)
        issues += self._check_dependency_cycles(tasks)
        issues += self._check_tool_duplication(agents)
        return ValidationResult(issues=issues)
```

### 6.3 템플릿 렌더링 엔진

```python
# caas_framework/codegen/engine.py
from jinja2 import Environment, FileSystemLoader

class CodeGenEngine:
    def generate_all(self, golden_data, agents, tasks, strategy, output_dir):
        files = {}
        # 모든 도메인 공통
        files["agents.py"] = self.render("agents.py.j2", {...})
        files["tasks.py"] = self.render("tasks.py.j2", {...})
        files["crew.py"] = self.render("crew.py.j2", {...})
        files["main.py"] = self.render("main.py.j2", {...})

        # CRUD_BASED / HYBRID
        if strategy.enable_crud:
            files["backend/models.py"] = self.render("backend/models.j2", {...})
            files["backend/api.py"] = self.render("backend/api.j2", {...})

        # 명시적 UI 요청 시만
        if strategy.enable_frontend:
            files["app.py"] = self.render("app.j2", {...})
        return files
```

class ValidationOrchestrator:
    validators = [
        CodeQualityValidator,    # 코드 품질 (복잡도, 스타일)

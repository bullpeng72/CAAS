## A

### Agent (에이전트)
CrewAI에서 특정 역할을 수행하는 AI 워커. 각 Agent는 고유한 역할(role), 목표(goal), 배경(backstory), 도구(tools)를 가짐.

**예시**: `agent_1: 데이터 분석가 (role: "Data Analyst", tools: [StatsTool])`

**관련 문서**: [13_Agent_Task_설계_가이드.md](../2_개발_실무_가이드/13_Agent_Task_설계_가이드.md)

### Agent Phase (에이전트 Phase)
Expert Agent가 작업하는 6개 Phase (CONCRETIZATION, DISCOVERY, ARCHITECTURE, DESIGN, DEVELOPMENT, DELIVERY).

**예시**: `RequirementAnalyst → DISCOVERY Phase`

### Architecture Design (아키텍처 설계)
Phase 2의 산출물. 시스템의 전체 구조, 컴포넌트, 데이터베이스 스키마, Tool 목록 포함.

**파일**: `architecture_design.json`

### AST (Abstract Syntax Tree)
Python 코드를 트리 구조로 파싱한 추상 구문 트리. CAAS는 AST를 사용해 코드 품질 분석 및 자동 수정 수행.

**예시**: `ast.parse(code) → FunctionDef, ClassDef, ...`

---

## B

### BaseTool
CrewAI의 도구 기반 클래스. 모든 커스텀 Tool은 `BaseTool`을 상속.

**예시**:
```python
class TodoCRUDTool(BaseTool):
    def _run(self, operation, **kwargs):
        ...
```

### Batch Processing (배치 처리)
여러 프로젝트를 한 번에 생성하는 기능. LLM 비용 절감 및 시간 단축 효과.

**명령어**: `caas batch generate --projects projects.csv`

### BMAD
구식 용어. **v0.3.0부터 "CAAS 6-Phase Methodology"로 변경됨**. 사용하지 말 것.

### Business Rule (비즈니스 규칙)
Golden Data의 일부. 도메인 고유의 제약사항 및 정책.

**예시**: `"할일 제목은 200자 이하", "HIGH 우선순위는 72시간 이내 완료"`

## C

### CAAS (CrewAI Agent Auto-generation System)
자연어 요구사항을 프로덕션 레디 멀티 에이전트 시스템 코드로 자동 변환하는 통합 패키지.

**버전**: v0.6.4

### CAAS 6-Phase Methodology
CAAS의 6단계 개발 방법론.
- Phase 0: Concretization (구체화)
- Phase 1: Discovery (발견)
- Phase 2: Architecture (설계)
- Phase 3: Design (상세 설계)
- Phase 4: Development (명세 생성)
- Phase 5: Delivery (코드 생성)

**관련 문서**: [10_CAAS_6Phase_개발_프로세스.md](../2_개발_실무_가이드/10_CAAS_6Phase_개발_프로세스.md)

### Caching (캐싱)
LLM 응답을 Redis에 저장하여 동일한 프롬프트 재사용 시 비용 및 시간 절감.

**설정**: `caas config --set llm_cache true`

### Checkpoint (체크포인트)
PM 승인 워크플로우를 위한 Human Approval Checkpoint 시스템 (v0.6.2).

**명령어**: `caas checkpoint approve --project <NAME> --checkpoint-id CP-3 --reviewer <NAME>`

**설명**: 7개 체크포인트 (CP-1 ~ CP-7) 승인 관리. Version Control Checkpoint (save/restore)는 v0.7.0+ 계획.

**관련 문서**: [52_Checkpoint_활용법.md](../5_엔터프라이즈_기능/52_Checkpoint_활용법.md)

### Code Analysis Agent (코드 분석 에이전트)
Phase 6에서 생성된 코드를 분석하고 런타임 오류를 수정하는 6번째 Expert Agent.

**추가 버전**: v0.4.0

### Code Quality Score (코드 품질 점수)
0-10 점수로 표현되는 코드 품질 지표. Docstring, Type Hints, Complexity, Duplication 등을 종합 평가.

**기준**: ≥8.5 (A 등급), ≥9.0 (S 등급)

### Completeness (완전성)
Phase 3 산출물 검증 메트릭. Golden Data의 모든 Feature가 Agent/Task로 매핑되었는지 확인.

**기준**: 100% (필수)

**명령어**: `caas analyze-completeness --project . --golden golden_data.json`

### CONVERSATIONAL_AI
CAAS 17개 도메인 중 하나. 대화형 AI 시스템 (챗봇, 가상 비서).

**구현률**: 98.7% ⭐⭐⭐⭐⭐

### CrewAI
멀티 에이전트 협업 프레임워크. CAAS가 생성하는 코드의 기반.

**공식 사이트**: https://crewai.com

### CRUD
Create, Read, Update, Delete의 약자. 데이터베이스 기본 작업.

**예시**: `TodoCRUDTool`

## D

### DAG (Directed Acyclic Graph)
방향성 비순환 그래프. Task 의존성 구조. 순환이 있으면 무한 루프 발생.

**검증**: `caas validate --validator dependency`

### DATA_ANALYSIS
CAAS 17개 도메인 중 하나. 데이터 분석 및 인사이트 도출.

**구현률**: 98.3% ⭐⭐⭐⭐⭐

**관련 문서**: [42_데이터분석_실습.md](../4_도메인별_실습/42_데이터분석_실습.md)

### Domain (도메인)
프로젝트의 분야/영역. CAAS는 17개 도메인 지원.

**예시**: `conversational_ai`, `task_management`, `data_analysis`

**관련 문서**: [60_프레임워크_데이터구조.md](./60_프레임워크_데이터구조.md)

### Distributed Execution (분산 실행)
Phase 1+2, Phase 5+6을 병렬로 실행하여 생성 시간 30% 단축.

**설정**: `enable_distributed=True` (기본값)

---

## E

### E2E Test (엔드투엔드 테스트)
사용자 시나리오를 처음부터 끝까지 테스트. Streamlit UI 기준으로 Selenium 사용.

**테스트 실행**: 수동으로 pytest 실행 (E2E 전용 CLI 명령어는 없음)
```bash
pytest tests/test_e2e_*.py -v
```

### Entity (엔티티)
Golden Data의 일부. 도메인 객체 및 속성 정의.

**예시**: `{"name": "todo", "attributes": ["id", "title", "description", "status"]}`

### Expert Agent (전문가 에이전트)
CAAS의 6개 핵심 에이전트.
1. Requirement Analyst
2. System Architect
3. Agent Designer
4. QA Specialist
5. Code Generator
6. Code Analysis Agent (v0.4.0+)

---

## F

### Feature (기능)
Golden Data의 핵심 요소. 시스템이 제공하는 기능 단위.

**예시**: `{"id": "f1", "name": "할일 생성", "inputs": ["title"], "outputs": ["todo_id"]}`

### Framework-First Architecture
CAAS의 아키텍처 원칙. UI-독립적 코어(`caas_framework`) + 다중 인터페이스(`caas_cli`, `caas_sdk`).

**장점**: Streamlit, FastAPI, React, VSCode Extension 등 다양한 UI 개발 가능.

---

## G

### Golden Data
Phase 0의 산출물. 구조화된 요구사항 (features, entities, constraints, business_rules).

**파일**: `golden_data.json`

**관련 문서**: [12_Golden_Data_활용법.md](../2_개발_실무_가이드/12_Golden_Data_활용법.md)

### Graph DB (그래프 데이터베이스)
지식 그래프 저장소. CAAS는 Neo4j 또는 Embedded 모드 지원.

**설정**: `graph_db="embedded"` (기본값)

---

## H

### Haiku (하이쿠)
Claude 3.5 Haiku 모델. 빠르고 저렴. 단순 작업에 적합.

**비용**: Sonnet 대비 70% 저렴

**사용**: `caas generate "..." --model haiku`

### Hierarchical Process (계층형 프로세스)
CrewAI의 실행 방식 중 하나. Manager Agent가 다른 Agent들을 조율.

**장점**: 복잡한 워크플로우 조율 가능

**설정**: `"process": "hierarchical"` in Golden Data

---

## I

### IPO Pattern (Input-Process-Output 패턴)
Agent 설계 패턴. 입력 수집 → 처리 → 출력 생성.

**예시**: 챗봇 (입력 분석 → FAQ 검색 → 응답 생성)

---

## J

### JSON Schema
Golden Data, Architecture, Specifications 등의 데이터 구조 정의.

**예시**: `AgentSpecModel`, `TaskSpecModel` (Pydantic 기반)

---

## L

### LLM (Large Language Model)
대형 언어 모델. CAAS는 OpenAI, Anthropic, Ollama 지원.

**예시**: `gpt-4`, `claude-3-5-sonnet-20241022`, `llama3:70b`

### LLM Judge (LLM 심사위원)
Quality Gate에서 LLM을 사용해 산출물 품질 평가.

**특징**: Haiku 모델 사용 (v0.4.0+) → 70% 빠른 평가

---

## M

### Manager LLM
Hierarchical Process에서 Manager Agent가 사용하는 LLM.

**기본값**: `gpt-4`

### Multi-Model Router (멀티 모델 라우터)
작업 복잡도에 따라 자동으로 모델 선택 (Haiku/Sonnet/Opus).

**사용**: `caas generate "..." --model auto`

---

## O

### Ollama
로컬 LLM 실행 플랫폼. 무료, 프라이버시 보장.

**설정**:
```bash
export OLLAMA_API_BASE="http://localhost:11434/v1"
caas config set llm.provider=ollama
```

### Ontology (온톨로지)
도메인 지식 그래프. 17개 도메인의 표준 패턴 저장.

**파일**: `data/ontology/domain_ontology.json`

### Opus (오푸스)
Claude 3 Opus 모델. 가장 정확하지만 느리고 비쌈.

**사용 사례**: 복잡한 금융/헬스케어 시스템

---

## P

### Phase (단계)
CAAS 6-Phase Methodology의 각 단계.

**Phase 0-5**: Concretization → Discovery → Architecture → Design → Development → Delivery

### Prompt Optimization (프롬프트 최적화)
LLM 토큰 수를 줄여 비용 절감. 장황한 설명 제거, JSON 구조화.

**효과**: 1,200 토큰 → 400 토큰 (67% 감소)

---

## Q

### Quality Gate (품질 게이트)
Phase 완료 시 품질 기준 검증. 기준 미달 시 재작업.

**메트릭**: Traceability 100%, Completeness 100%, Code Quality ≥8.5

**설정**: `strict_quality_gates=True` (v0.4.1+)

**관련**: [32_품질_검수_체크리스트.md](../3_프로젝트_관리_PM/32_품질_검수_체크리스트.md)

---

## R

### RAG (Retrieval-Augmented Generation)
벡터 검색 기반 질의응답. Knowledge Base 도메인에서 사용.

**예시**: FAQ 검색 + LLM 응답 생성

### Requirement Analysis (요구사항 분석)
Phase 1의 산출물. 도메인 분류, 기능 분석, 엔티티 식별.

**파일**: `requirement_analysis.json`

### Role (역할)
Agent의 역할 정의.

**예시**: `"role": "데이터 분석가"`, `"role": "FAQ 검색 담당자"`

---

## S

### Sequential Process (순차 프로세스)
CrewAI의 실행 방식 중 하나. Task를 순차적으로 실행.

**장점**: 단순, 예측 가능

**설정**: `"process": "sequential"` in Golden Data

### Sonnet (소네트)
Claude 3.5 Sonnet 모델. 균형잡힌 성능/비용. CAAS 기본 모델.

**사용**: `caas generate "..."` (기본값)

### Specifications (명세)
Phase 4의 산출물. CrewAI 실행에 필요한 최종 명세.

**파일**: `specifications.json`

### Streamlit
Python 기반 웹 UI 프레임워크. CAAS의 기본 UI 옵션.

**생성**: `caas generate "..." --ui streamlit`

---

## T

### Task (작업)
CrewAI에서 Agent가 수행할 작업. Description, Expected Output, Agent, Context 포함.

**예시**: `task_1: 사용자 입력 수집 (agent_1)`

### TDD (Test-Driven Development)
테스트 주도 개발. CAAS는 Golden Data 기반 테스트 자동 생성.

**명령어**: `caas tdd generate --project . --golden golden_data.json`

**관련 문서**: [50_TDD_자동화_가이드.md](../5_엔터프라이즈_기능/50_TDD_자동화_가이드.md)

### Tool (도구)
Agent가 사용하는 기능. BaseTool 상속.

**예시**: `TodoCRUDTool`, `FAQSearchTool`, `ChartGeneratorTool`

**관련 문서**: [14_도구(Tools)_개발_가이드.md](../2_개발_실무_가이드/14_도구(Tools)_개발_가이드.md)

### Traceability (추적성)
Phase 2 검증 메트릭. Golden Data의 모든 Feature가 Architecture의 Component로 매핑되었는지 확인.

**기준**: 100% (필수)

**명령어**: `caas traceability --golden-data golden_data.json --agents agents.json --tasks tasks.json`

**참고**: 독립 명령어로 제공 (validator 옵션 아님)

---

## V

### Validation (검증)
산출물의 정확성 및 완전성 확인. 7개 Validator 지원.

**명령어**: `caas validate --validator all`

### Validator (검증자)
7개 검증 모듈.
1. CodeQualityValidator
2. CrewAIValidator
3. DependencyValidator
4. GoldenDataValidator
5. OntologyValidator
6. Python311Validator
7. TaskValidator

---

## W

### Webhook
외부 서비스에서 보내는 HTTP POST 요청. CAAS는 Webhook 수신/처리 시스템 생성 지원.

**도메인**: `webhook_handler`

**관련**: [43_API통합_실습.md](../4_도메인별_실습/43_API통합_실습.md)

### Workflow (워크플로우)
Agent들의 협업 흐름. Sequential 또는 Hierarchical.

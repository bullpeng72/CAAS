## CLI로 빠른 시작

### 🔷 첫 프로젝트 생성

CLI는 `caas_framework`를 직접 사용하므로 별도의 API 서버가 필요하지 않습니다.

**첫 프로젝트 생성:**
```bash
# 기본 생성
caas generate "사용자 인증 기능이 있는 할일 관리 시스템 만들기"

# 옵션 포함
caas generate "블로그 플랫폼 만들기" \
  --domain CONTENT_CREATION \
  --output ./my-blog \
  --deployment kubernetes
```

### 🔷 옵션 2: Python 코드로 직접 사용

**Python 스크립트에서 직접 사용:**

```python
from caas_framework.framework import CrewAIFramework
import asyncio

async def main():
    # 프레임워크 인스턴스 생성
    # llm_provider는 .env 파일 또는 caas config로 설정 가능
    framework = CrewAIFramework()
    await framework.initialize()

    # 프로젝트 생성
    result = await framework.generate_from_requirement(
        requirement="할일 관리 시스템 만들기",
        domain="TASK_MANAGEMENT",
        output_dir="./generated_from_py"
    )

    await framework.close()

    # 결과 확인
    if result.success:
        print(f"✅ Generated {len(result.files)} files")
        print(f"Completeness Score: {result.completeness_score}/100")
        print(f"Implementation Rate: {result.implementation_rate:.1f}%")
    else:
        print(f"❌ Generation failed: {result.error}")

asyncio.run(main())
```

**진행률 추적 예제:**

```python
from caas_framework.framework import CrewAIFramework
from caas_framework.reporting import ProgressReporter, VerbosityLevel
import asyncio

async def main():
    # Progress Reporter 설정
    reporter = ProgressReporter(verbosity=VerbosityLevel.VERBOSE)

    # 프레임워크 인스턴스 생성
    framework = CrewAIFramework(progress_reporter=reporter)
    await framework.initialize()

    # 실행 (실시간 진행률 표시)
    result = await framework.generate_from_requirement(
        requirement="블로그 플랫폼 만들기",
        domain="CONTENT_CREATION"
    )

    await framework.close()

    # 결과 요약
    print("\n" + "="*60)
    print(f"✓ Done! Files saved to: {result.output_dir}")
    print(f"✓ Completeness: {result.completeness_score}/100")
    print(f"✓ Implementation Rate: {result.implementation_rate:.1f}%")

asyncio.run(main())
```

**참고**: CAAS는 **Framework-First 아키텍처**입니다. CLI 또는 Python 코드로 직접 프레임워크를 사용합니다.

## 🔥 BMAD Phase 기능 (v0.2.0+)

CAAS는 더 나은 코드 생성을 위해 BMAD 6-Phase 워크플로우를 사용합니다.

### BMAD Phase란?

- **Phase 0-1**: 요구사항 분석 및 구조화
- **Phase 2**: 아키텍처 설계 및 추적성 매트릭스 생성
- **Phase 3-4**: 에이전트/태스크 설계 및 완전성 검증
- **Phase 5**: 코드 생성 및 배포 준비

### Phase 기능 제어

**CLI:**
```bash
# 전체 워크플로우 실행 (기본값)
caas generate "REST API 만들기"

# 일부 Phase 건너뛰어 빠른 프로토타이핑
caas generate "REST API 만들기" \
  --no-traceability        # Phase 2 건너뛰기
  --no-completeness        # Phase 3 건너뛰기
  --gap-filling            # 자동 갭 채우기 활성화
```

**Python:**
```python
result = await framework.generate_from_requirement(
    requirement="REST API 만들기",
    enable_traceability=True,
    enable_completeness_validation=True,
    enable_gap_filling=False
)
```

### Phase 결과물

**Phase 2 출력**: `traceability_matrix.json`
```json
{
  "features": {
    "F001_사용자_로그인": {
      "tasks": ["T001_사용자_인증", "T002_토큰_생성"],
      "code_files": ["src/auth.py", "src/models.py"],
      "coverage": "100%"
    }
  }
}
```

**Phase 3 출력**: `completeness_report.json`
```json
{
  "overall_score": 87.5,
  "feature_implementation": {
    "fully_implemented": 10,
    "partially_implemented": 2,
    "not_implemented": 0
  },
  "recommendations": [
    "src/auth.py의 login()에 에러 처리 추가",
    "API 엔드포인트에 rate limiting 구현"
  ]
}
```

## 🐛 일반적인 문제

### CLI: "caas: command not found"

**해결책:**
```bash
pip install -e ".[cli]"
```

### 생성: "OPENAI_API_KEY not set"

**해결책:**
```bash
# .env 파일이 프로젝트 루트에 있고 API 키가 있는지 확인
cat .env | grep OPENAI_API_KEY

# 또는 터미널에서 설정
export OPENAI_API_KEY=sk-your-key
```

## 💡 프로 팁

### 1. 상세한 요구사항 사용

**나쁜 예:**
```
할일 앱 만들기
```

**좋은 예:**
```
다음 기능을 가진 할일 관리 시스템 만들기:
- 사용자 인증 (이메일/비밀번호)
- 할일 CRUD 작업 (제목, 설명, 마감일, 우선순위)
- 사용자에게 할일 할당
- 상태와 우선순위로 할일 필터링
- REST API 엔드포인트
- PostgreSQL 데이터베이스
```

### 2. 더 나은 결과를 위해 도메인 지정

```bash
# 도메인 없이 (일반)
caas generate "금융 분석기 만들기"

# 도메인 포함 (최적화됨)
caas generate "금융 분석기 만들기" --domain DATA_ANALYSIS
```

### 3. 프로덕션 코드 생성 시 모든 품질 기능 사용

```bash
# 개발/프로토타입 (빠름)
```
